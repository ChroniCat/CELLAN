# UI-29.2 图标字形与四档尺寸自检

日期：2026-11-16　范围：`crates/app/src/ui_icons.rs`（138 个矢量图标）

## 1. 这轮的判定方式

验收要求「所有图标在 16/20/24/32px 清晰」，且「截图测试不能只验证按钮存在」。
本机 `vision_analyze` 连续超时（人工看图这条路断了），所以用两层机械判定：

1. **形状级**（`every_icon_draws_ink_inside_its_box_at_four_sizes`）：每个图标在四个尺寸、
   彩色/单色两种画法下，收集 egui 画出的全部 Shape，算墨迹外框——
   - 外框必须落在图标盒子内（允许 6% 外扩，`draw_excel` 本来外扩 4%）；
   - 墨量（外框面积占比）≥ 6%，防止图标缩成点或画空；
   - 形状列表不能为空。
2. **像素级**（`audit_sheet.py`）：把 138 个图标 × 一个尺寸铺成 12 列对照表，
   截图后逐格数非白像素——空白格（<2%）和糊满格（>92%）都要为 0，并给出墨量分布。

两层合起来的强度：形状级能抓「画出界/画空」，像素级能抓「真的没渲染出来」和「糊成一坨」。

## 2. 抓到的两个真缺陷

两个都是**用字体字形当图标**导致的，换成矢量笔画后消失。

| 图标 | 现象 | 根因 | 修法 |
|---|---|---|---|
| `Comma` | 16px 档外框 y 到 36.5（盒子只到 32），24px 档到 46.5（盒子 40） | `pen.text(",", 16.4, 12.6, 21.0)` —— 21 个网格单位大的字形，逗号尾巴下伸到 y≈26 | 改成矢量：两点 + 一条 2.6 粗的尾巴，整体落在 10.6..18.4 |
| `FormulaView` | 32px 档顶边跑到 13.5（盒子从 16 开始），高出 2.5px | `pen.text("fx", …, 8.0)` 的行高约 25px，居中锚点把上半截顶出盒子 | "f" 和 "x" 改成 4 条 `polyline` + 1 条 `ln`，与网格线同粗 |

两处修复后，形状级自检从 10 项失败降为 0；单色/彩色两种画法都过。

## 3. 四档像素自检结果（138 个图标/档）

| 尺寸 | 空白格 | 糊满格 | 墨量 min / 中位 / max |
|---|---|---|---|
| 16px | 0 | 0 | 0.086 / 0.254 / 0.562 |
| 20px | 0 | 0 | 0.070 / 0.225 / 0.560 |
| 24px | 0 | 0 | 0.082 / 0.215 / 0.625 |
| 32px | 0 | 0 | 0.071 / 0.203 / 0.609 |
| 24px @150% | 0 | 0 | 0.079 / 0.207 / 0.515 |

墨量中位数随尺寸增大略降（0.254 → 0.203），符合「线宽固定、面积按平方增长」的预期；
150% 档与 100% 档分布接近，说明放缩没有引入额外墨块。

## 4. 线宽下限

`icon_stroke_width_never_drops_below_one_pixel`：138 图标 × 4 尺寸，任何
`Rect.stroke` / `LineSegment.stroke` / `Path.stroke` 都不得 < 1.0。
`paint()` 里 `w = (1.6 * s).max(1.0)` 保证 16px 档（s=0.667）不会细到看不见；自检通过。

## 6. 边界

- **没有人工视觉评审**：`vision_analyze` 本轮连续超时，所有结论都来自形状统计与像素统计，
  不能声称「肉眼看起来和 Excel 一致」。
- 墨量阈值（<2% 空白、>92% 糊满、外框 6% 容差）是这轮定的口径，不是 Office 的官方数字；
  它只能保证「有墨、没出界、没糊死」，不能保证「和 Excel 图标长得像」。
- 对照表只在浅色底、`draw_excel` 彩色模式下截；深色按钮悬停态的图标未单独截。
- 工具提示、快捷键标注这类文本不属于图标，未纳入本切片。
