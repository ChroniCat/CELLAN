# Sheets Native 对标 Excel 与 WPS 的需求审查

审查日期：2026年11月12日，Asia/Shanghai。源码基线：`df48672`，分支 `main`。交付对象：产品负责人、使用 Hermes 内 DeepSeek 的实施者、回归验收人员。

当前产品已经有相当多的表格能力，主要问题是**已有功能的正确性、入口一致性、文件保真和呈现质量**。应先修复输入丢失、公式计算、保存失败处理和写入权限检查，再完善高频操作，最后扩展高级能力。旧清单按控件名称统计的“完成率”不能描述当前产品质量。

本需求包包含 **61 个有编号的任务**（19项P0、35项P1、7项P2），进一步拆为148个实施切片。每项包含现状、对标行为、修改要求和验收标准；任务索引另列优先级、依赖、建议改动范围、工作量级别和拆分建议。这里的“待实施”不表示整项功能完全缺失，而是该项描述的差距尚未解决。

## 4 最重要的差异

| 问题 | 本项目现状 | Excel / WPS基准 | 证据与任务 |
|---|---|---|---|
| 输入后Enter/Tab | 缓冲消失，选区移动，A1仍为空；dirty=false、undo为空 | 提交输入并移动选区 | D1事件级，UI-01；原生键盘复测列入验收 |
| 错误增量传播 | A1=1/0、B1=1、C1=SUM(A1,B1)，改B1=2后C1变2；全算又变错误 | 两款修改前后均为#DIV/0! | D3，C01 |
| 二维数组 | SEQUENCE(2,2)+1变成1×4 | 两款均为2×2 | D3，C02 |
| 数组广播 | SUM({1;2}+{10,20})=33 | 两款均为66 | D3，C02 |
| 公式字符串 | `="_xlfn.TEXT"`被改成`="TEXT"` | 两款保留_xlfn.TEXT | D3，C03 |
| 日期体系 | date1904=1、序列1显示1900-01-01 | 两款对应1904-01-02 | D3，C04 |
| 空引用比较 | A1为空时等于0/空字符串均FALSE，小于0为TRUE | 两款依次TRUE、TRUE、FALSE | D3，C05 |
| 保存补丁失败 | 多个关键子步骤Err只日志，仍可能回报保存成功 | 需求合同要求保存完整才清dirty | S，C13；尚待故障注入 |
| 快捷键 | Ctrl+S等有说明，主键盘分发未注册 | Ctrl+S执行保存 | S，UI-02；需真实按键回归 |
| 保护与清除 | 不同入口绕过统一检查；区域Delete只更新活动格依赖 | 写入权限、重算、撤销应与入口无关 | S，UI-03/04 |
| 查找与替换 | 查找按全宽扫描并400万步截断；全部替换缺事务 | 有效区域可完整查找，批量替换可撤销 | S，UI-05 |
| 粘贴 | Ribbon/右键与Ctrl+V使用不同来源；选择性粘贴公式偏移有误 | 各入口取最新系统剪贴板，相对引用正确平移 | S，UI-06/07 |
| 文本对齐 | General文本居中，长文字从中段裁剪 | 同表两款均左对齐，开头可见 | V+S，C22 |
| 字体 | “等线/微软雅黑”等映射同一思源字族 | 使用本机字体；本轮字形明显不同 | V+S，UI-14；样式解析bold=false，不能误归为读错粗体 |
| 功能区 | 1440宽已截去右端常用组；760宽仅少数组可见 | Excel分组较紧凑；WPS本轮全部高频组可见 | V+S，UI-13 |
| 缩放 | 调用全应用zoom，标题和Ribbon一起变大 | 表格缩放与系统UI比例分离 | S，UI-12 |
| 格式窗口 | 4个页签，固定示例数字，缺填充/保护完整编辑 | 完整格式编辑按类型组织 | V+S，UI-08/15、C15 |
| PDF输出 | 独立简化渲染，使用原始显示值，缺对象及多种格式 | 输出可打印的表格内容与数字格式 | S，C16、QA-09；本轮未完成PDF三方渲染 |

## 6 优先级规则与发布门槛

- **P0：** 输入或数据可能丢失、算错、保存/取消不可信、权限旁路，以及支撑这些修复的最小测试基础。P0完成前，不应把版本称为可替代Excel/WPS的日常编辑工具。
- **P1：** 高频操作完整性、显示保真、常用兼容、打印和输入效率。P0闭环后优先完成财务/报表用户每天会遇到的路径。
- **P2：** 高级能力、低频扩展与进一步体验打磨。已有能力出现数据丢失风险时，风险部分仍按P0处理。
- **P3路线决策：** Power Query/M语言、完整VBA解释器、真正多窗口与同步滚动、线程协作评论、墨迹/3D/SmartArt、云翻译/账号生态、ETS预测、时间线切片器等。暂不自动进入本轮61项实施队列；需先给目标用户、数据模型、依赖、预算和兼容范围。旧文档“明确不做”不是本轮永久排除授权。

发布至少需要：所有P0验收通过；无丢内容的成功保存、无取消后写盘、无输入丢失；约定三方往返无修复提示；所有启用命令有真实行为；支持矩阵写明剩余限制；测试输出区分passed/failed/ignored/filtered/blocked。存在已知不支持功能时，应保留原始内容、说明限制，必要时只读或另存，不能静默替换结果。

不要求复刻广告、会员入口、头像、商标或云推广条。建议保留WPS式文档标签，采用Excel式常用命令组织，以本项目自己的字体、间距、图标和状态规范统一视觉。

## 7 现有测试与新探针的结论

当前源码重新编译后：核心测试 **457通过、0失败、34 ignored**；应用单元测试 **100通过、0失败、4 filtered**；原生UI回归 **8通过、0失败、9 ignored**。详见 [verification.json](evidence/verification.json)。4项网络测试有监听/端口与环境风险，本轮明确跳过，不能计入通过。

额外加入后移除的UI-01诊断测试按正确结果断言失败，确认输入提交缺陷；诊断源码和关键日志已保留，仓库业务源码与原测试文件没有残留修改。该结果与已有套件通过不矛盾，说明现有断言存在覆盖缺口。不要修改失败断言来让结果变绿。

本需求交付不包含应用修复。独立审查确认旧清单的图表、页面设置、公式分类、外链、真实透视表等“缺失”描述已失效；拒绝继续使用控件匹配率。字体观感偏粗也没有被武断认定为读取bold错误，样式读取实测为false。输入提交最初是源码推断，随后由事件探针升级为动态证据。尚未完成的原生IME、DPI、打印和网络验证如实列入后续验收。
