# QA-05.2 真实系统 DPI 100/125/150/200（2026-11-18）

程序：`target/debug/app.exe`（本轮修复后的构建）。
显示器：Windows 显示设置实际为 **2560×1440**；会话切到本机 console 后 `GetSystemMetrics(SM_REMOTESESSION)=0`，由 `work/probe/qa05_probe_console.ps1` 保证设置项可用。
设置方式：真实的 Windows「系统 → 显示 → 缩放」ComboBox（UIA `ExpandCollapse` + `SelectionItem`），不是 `SC_PPP`；每个档位后用 `GetDpiForWindow` 读取本应用窗口，再以 `SC_WIN_W=1280 SC_WIN_H=720` 启动应用（逻辑 1280×720），窗口物理尺寸随系统 DPI 等比变化。
截图：应用窗口 `PrintWindow`（DPI-aware 进程），不是 `SC_SHOT` 的 framebuffer 放大。

## 关键读数

- DPI 比例严格为 96→120→144→192（100%→125%→150%→200%），窗口物理宽高 1280×720→1600×900→1920×1080→2560×1440，宽高比保持 16:9。
- 每个档位截图由真实 Windows 缩放后的窗口生成；`qa05_once.ps1` 在设置完成后打印：
  - `SCALE=100% (Recommended) DPI=96 RECT=150,78,1280x720 SCREEN=2560x1440`
  - `SCALE=125% DPI=120 RECT=239,160,1600x900 SCREEN=2560x1440`
  - `SCALE=150% DPI=144 RECT=437,342,1920x1080 SCREEN=2560x1440`
  - `SCALE=200% DPI=192 RECT=323,196,2560x1440 SCREEN=2560x1440`
- 四档均以逻辑 1280×720 运行；125/150/200% 的物理窗口分别为 1600×900/1920×1080/2560×1440，没有把 `SC_PPP` 当系统 DPI，也没有用旧版 `SC_SHOT` 隐藏布局问题。
- 截图核对（`vision_analyze`）逐档确认：ribbon 全部组（含最右「编辑」「更多」）、窗口控制、状态栏、Sheet 标签、水平/垂直滚动条均完整；无标签裁切、重叠或不可触达控件。
- 字号/网格随 DPI 等比放大；同一逻辑 1280×720 下四档的列数/行数与控件相对位置一致（100% 列 A–Q/行 1–19；125/150/200% 视觉相同，仅物理像素放大）。
