# QA-05.2：100/125/150% 缩放布局复测（2026-11-17）

## 方法

本机 RDP 不能改真实系统 DPI，因此用应用自带的 `SC_PPP` 强制 `pixels_per_point`，
并同步放大 framebuffer，使**逻辑尺寸保持 1440×900**：

| PPP | SC_WIN_W×H | PNG 实际尺寸 | 逻辑网格 pane |
|---|---|---|---|
| 1.00 | 1440×900 | 1440×900 | `(0,255,1423,829)` / avail 1423×574 |
| 1.25 | 1800×1125 | 1800×1125 | `(0,255,1423,829)` / avail 1423×574 |
| 1.50 | 2160×1350 | 2160×1350 | `(0,255,1423,829)` / avail 1423×574 |

命令（每次 `SC_SHOT_EXIT=1`，否则窗口常驻）：

```
SC_PPP=1.25 SC_WIN_W=1800 SC_WIN_H=1125 SC_ANIMATION_TIME=0 \
  SC_DUMP=... SC_SHOT=work/probe/dpi2_1.25.png SC_SHOT_EXIT=1 \
  target/release/app.exe crates/core/tests/fixtures/qa09/a11y.xlsx
```

## 结果

- 三档 `SC_DUMP` 的 pane rect、avail、first cell、选择框完全一致
  （`rect=(0,255,1423,829)`，`avail=[1423.0 574.0]`，`first=(2,2)`）；
- 三张 PNG 分别为 1440×900 / 1800×1125 / 2160×1350；把后两张 Lanczos
  缩回 1440×900 后与 1.0 基准的 RMSE 为 **11.91 / 11.26**（0–255 量纲），
  非白像素占比 0.276 / 0.289，说明不是空白/错位图；
- 2.0 档受本机 RDP 最大 framebuffer 2560×1440 限制，窗口没能到 2880×1800，
  `SC_DUMP` pane 变成 `1263×649`，**该档不作为通过证据**。

## 结论与缺口

这证明应用布局按 `pixels_per_point` 等比缩放、逻辑几何不变；但它**不是**
真实系统 DPI 切换，也没有多显示器跨屏拖动。QA-05.2 仍保持待验收，
not_done 只删掉「100/125/150 布局未测」，保留「真实系统 DPI/多显示器」。
