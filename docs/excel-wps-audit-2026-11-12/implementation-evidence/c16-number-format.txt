# C16.1 打印/PDF 数字格式与字体显示

日期：2026-11-13 20:25 CST
范围：`crates/core/src/print.rs`、`crates/core/src/pdf.rs`、合成夹具 `crates/core/tests/fixtures/c16/number_formats.xlsx`。

## 修复前

`print::draw_cell` 直接调用 `Value::display()`：

- 日期按 Excel 序列号显示，而不是 `yyyy-mm-dd`；
- `0.15` 显示为 `0.15`，而不是 `15%`；
- `1234.5` 显示为 `1234.5`，而不是 `¥1,234.50`；
- `-123.45` 显示为 `-123.45`，而不是分段格式的负数段。

PDF 的 Type0 字体没有 `ToUnicode`，即使字形画对，复制/检索得到的也是乱码。

## 修复

1. `draw_cell` 增加 `DateSystem` 参数；单元格有 `style.format` 时调用
   `style::format_value_in(date_system, value, format)`，否则保留 `display()`。
2. PDF 生成器增加第 7 号对象 `ToUnicode` CMap，映射字体 `cmap` 的字形号到
   UTF-16BE；Type0 字典增加 `/ToUnicode 7 0 R`，页面对象号从 8 开始，避免对象冲突。
3. ToUnicode 按 100 个 `bfchar` 分块，兼容 PDF 阅读器的 CMap 限制。

## 实际执行与读取

导出：

```text
cargo run -p sheetcore --offline --example c16_pdf -- \
  crates/core/tests/fixtures/c16/number_formats.xlsx \
  C:/Users/Administrator/AppData/Local/hermes/cache/scratch/c16_formatted.pdf
-> pages=1
SHA-256: 88fce948388bdcd0fa325766843eb1fc61dd75031fd61478794800dbe80598e5
```

用 pypdfium2 的 `get_textpage().get_text_range()` 读回（与屏幕字体无关，直接读 PDF 文本层）：

```text
日期 2026-01-15
百分比 15%
货币 ¥1,234.50
负数 -123.45
第 1 / 1 页
```

`pdftotext` 也能读出 `2026-01-15`、`15%`、`1,234.50`、`-123.45`，但把 `¥` 显示成
替换字符；pypdfium2 读出完整 `¥`，因此以上以 pypdfium2 的结果为准，并保留这个
阅读器差异。

单元测试：

```text
cargo test -p sheetcore --offline --test pdf_export
-> 3 passed; 0 failed; 0 ignored
```

其中 `number_formats_are_used_during_pdf_export` 验证：

- 夹具和子集字体存在；
- PDF 有 `Tj` 文字指令；
- ToUnicode 中存在 U+00A5 映射，防止只画字形不写文本层。

## 诚实边界

- 只覆盖 C16.1 的数字格式与文本层；负数 `[Red]` 的颜色仍未绘制，属于 C16.2 的样式/颜色范围，不能据此把 C16 父项记完成。
- 没有做逐页与 Excel/WPS 视觉矩阵；目前是单页自建夹具的文本层验收。
- 字体是仓库现有 SIL OFL 子集；不引入系统字体。`¥` 在 pdftotext 下的替换问题已记录，换阅读器可读。
