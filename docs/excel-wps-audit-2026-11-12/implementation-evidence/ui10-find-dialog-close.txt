问题
- Ctrl+H 只走 find_open_new_session，没有设置 find.tab=1，打开后仍停在“查找”页。
- 查找对话框底部“关闭”按钮在闭包里直接写 self.find.open=false，函数末尾又执行
  self.find.open = open，把关闭结果覆盖回 true；X/Esc 不会触发这个覆盖，所以只有按钮失效。

### 发现的真实缺陷 1：关闭按钮点击穿透
- 复现：A1 选中 → Ctrl+H 打开对话框 → 按原 capture 坐标点底栏“关闭”
  (1038,561)。对话框关闭，但选区变成 O16（“关闭”正下方的格子）。

- 证据：`ui10-prefix-clickthrough.png`（点×后选区为 L4）。
- 根因：网格用原始 `primary_pressed()` + `press_origin()` 落选区，早于 / 独立于
  egui 窗口的 pointer blocking；关闭按钮同一次按下既关窗又选中背后格子。
- 修复：`SheetApp.dialog_modal`（`find.open`）在打开期间让网格 pane 只画不响应
  （`Sense::hover()`、清 `grid_press`、禁用滚动和原始按下选区）。
- 回归：新增 `modal_dialog_click_does_not_select_grid_behind`；modal=true 时点 C3
  选区不变，modal=false 时同一点恢复选中 C3。修复前失败，修复后 1 passed。

## 17:25 追加：关闭按钮获得焦点时单个 Enter 的残余键路径

监督指出 `egui 0.31 context.rs:1262` 的 `key_pressed` 只把 `clicked` 置真、
不消费 Enter；`find_dialog` 关闭后 `stop_text_input()` 让同帧
`ctx.wants_keyboard_input()` 变假，`update` 后段 `handle_keys` 会把同一个 Enter
推进网格。该路径与鼠标关闭不同，必须单独覆盖。

修复：`update` 中网格键盘处理改为

```rust
if !self.backstage && !self.dialog_modal {
    self.handle_keys(ctx);
}
```

`dialog_modal` 在帧首保存 `find.open`，因此关闭帧仍为 true：该帧既不处理指针，
也不处理网格键盘；下一帧才恢复。

真实 egui 窗口事件回归（`ui_frame` 走完整 `eframe::App::update`，不是直接调
`handle_keys`）：`enter_on_focused_dialog_close_does_not_advance_selection`

1. B2 填 `old`，`sel=(1,1)`；打开查找/替换框。
2. 先跑一帧画出对话框；用真实 `egui::Id::new(("dlgwin", "查找与替换")).with("close")`
   `request_focus`，把焦点放到标题栏关闭按钮（该 Id 即键盘焦点落到关闭按钮时的控件 Id；
   这模拟 Tab 最终到达该按钮后的状态，不依赖无头环境不稳定的焦点遍历顺序）。
3. 发送单个 Enter：对话框关闭，选区仍为 B2，没有推进到 B3。
4. 下一帧发送文本 `9`，再发 Enter：B2 从 `old` 变为 `Number(9.0)`，
   证明关闭后键盘焦点确实回到网格，而非被隐藏控件吞掉。

负向验证：临时移除 `&& !self.dialog_modal` 后同一测试 FAILED（`ui10_enter_neg.log`），
恢复后 1 passed。
