日期：2026-11-12 UTC+08   环境：source scripts/audit_env.sh（TEMP/TMP/LOCALAPPDATA 隔离）

一、原要求与现状核查
--------------------
core-requirements.md C13 原文要求「只有临时输出通过完整性检查才原子替换」，
验收要求「断电/文件占用/权限不足测试与现有原子保存测试一起通过」。

排查结果：**之前没有最终产物校验**。
`save_atomic` 的流程是 `save(&tmp)` 成功 → 直接 `rename(tmp, path)`；
`save_plain_base` 结尾 `Ok(())`。除 `save_atomic_with_receipt` 里事后读
`patch::sheet_targets`（读已落盘的文件，属事后检查、且只覆盖工作表身份），
没有任何「写完之后、替换之前」的校验点。所以「写步骤报成功但产物已损坏」会被
原样覆盖上目标文件。

二、实现：verify_saved_package
------------------------------
`crates/core/src/xlsx.rs` 新增 `pub fn verify_saved_package(path: &Path) -> Result<()>`：

1. XLS 走 `xls_read::load`（CFB 解析成功才算完整）；
2. XLSX/XLSM：ZIP 中央目录能打开（截断会在这里失败）；
3. 必需部件齐全：`[Content_Types].xml`、`_rels/.rels`、`xl/workbook.xml`、`xl/_rels/workbook.xml.rels`；
4. 逐条目读到底（CRC 错误/条目被截断会暴露）；
5. 上述四个 XML 逐事件解析 + **开始/结束标签深度计数**（读到 EOF 深度不为 0 即视为截断）；
6. `[Content_Types].xml` 里每个 Override 的 PartName 必须真的在包里；
7. `xl/_rels/workbook.xml.rels` 指向的每个部件必须存在（外链/相对上级路径除外）。

接入点两处，都在 rename/encrypt 之前：
- `save_atomic`：写完临时文件 → `corrupt_tmp_for_test` → `verify_saved_package` → rename；
  校验失败删临时文件并返回 `保存产物完整性校验失败，未覆盖 <目标>`。
- `save`（带打开密码）：加密前对临时明文做同样校验。

故障注入 `SC_CORRUPT_TMP=truncate|drop-part|drop-sheet|corrupt-xml`：
在「写完之后」把临时文件弄坏，用来复现「写步骤全部成功、产物不可用」这一路径。
另一个注入 `SC_SAVE_PAUSE_MS=<ms>` 把「临时文件已写好、还没替换」的窗口拉长，
供中断测试在窗口内强杀进程。两者未设置时零影响。

四、边界（不得含糊）
--------------------
- `killed_during_save` 模拟的是**进程被终止**：临时文件已写、尚未替换。
  它覆盖不了物理断电特有的问题（页缓存未落盘、目录项顺序、NTFS 日志回放），
  也不能证明「掉电后 .saving- 残留文件不会出现」。物理断电本机无法安全模拟。
- 真实占用用同进程的独占句柄构造，与「另一个进程（Excel/Office）打开」在 Windows
  共享语义上等价（都让 rename 拿到 ERROR_SHARING_VIOLATION），但没有真的启动 Office。
- 门禁对超大文件的成本：需要完整读一遍 ZIP 条目做 CRC，保存耗时随文件线性增加；
  106MB 级工作簿的实测属性能项（C13 补验未做基准，属 QA-06 性能）。
- 图表/宏等复杂部件的**内容**保真不属本条（属 C19/QA-01）；本条只保证「部件在、能读、关系不断」。

五、复核补正（同日，第二次独立审查）
------------------------------------
审查指出的四个在建风险，逐条落实：

1. **按扩展名识别 .xls 不可靠**：临时路径是 `.~name.xls.saving-<pid>`，扩展名是 `saving-<pid>`。
   已改为**按文件头**识别：`PK\x03\x04|PK\x05\x06|PK\x07\x08` → ZIP；
   `D0 CF 11 E0 A1 B1 1A E1` → CFB；其它 → 直接判为无法识别。
2. **加密 XLSX 是 CFB 容器，不能当 ZIP 拒**：CFB 分支先试 `xls_read::load`（老 .xls），
   失败则用 `cfb::Compound` 找 `EncryptionInfo` + `EncryptedPackage` 两条流，齐了才算完整。
   新增用例 `encrypted_workbook_passes_the_gate_even_though_it_is_cfb`：加密保存 → 断言前 8 字节是 CFB 签名 →
   `verify_saved_package` 通过 → 用密码解回来核对内容。
   注意：`crypto::encrypt` 之前会对**明文临时件**做同一门禁（真正的深检查在这里），
   所以加密产物本身只做容器级检查，不假装能不解密就验内容。
3. **关系目标解析**：以前 `../` 直接 `continue`（漏检），`/xl/...` 会被拼成 `xl/xl/...`。
   现在 `resolve_part()` 以 `xl/` 为基准做真正的路径归一：`..` 逐级上退（越出包根即报错）、
   前导 `/` 视为包内绝对、`#fragment` 去掉、`TargetMode="External"` 不参与检查。
   新增用例 `relationship_targets_are_resolved_the_xml_way`：把 `worksheets/sheet1.xml` 改写成
   `../xl/worksheets/sheet1.xml`（等价路径），门禁必须仍然通过——证明它真的解析而不是跳过。
4. **XML 只数深度太松**（空文件、多根都能过）：改为 `check_single_root()`：根元素只能有一个、
   根闭合后不能再出现元素或非空白文本、必须有根、结束后深度必须归零。

六、门禁上线后立刻抓到的真实缺陷（已修）
----------------------------------------
`cargo test -p sheetcore` 首轮：**add_sheet_save 的 2 个用例 FAILED**
（`adding_a_sheet_then_save_atomic_keeps_every_sheet`、`excel_authored_base_keeps_sheets_after_adding_one`），
报 `[Content_Types].xml 声明了不存在的部件 /xl/worksheets/sheet2.xml`。

复现（临时导出，随后删除）：加一张表后保存，包里实际是
`xl/worksheets/sheet1.xml` + `xl/worksheets/native-sheet-5-0.xml`，
而 `[Content_Types].xml` 仍留着旧的 `/xl/worksheets/sheet2.xml` Override。
根因：`prune-content-types` 跑在 staged 补丁**之前**，之后补丁把 sheet2 改名成 native-sheet-*，
留下悬空声明——Excel 打开这种包会提示需要修复。

修复：`save_plain_base` 在所有部件落盘（含 `commit_stage`、透视表、表格同步）之后再执行一次
`prune-content-types-final`。修复后 add_sheet_save 5 项全过，全量 sheetcore **57 个测试二进制、0 失败**（EXIT=0）。

这条同时说明门禁不是「加个安慰性检查」：它抓到了既有代码里真实存在的包损坏路径。

七、第三次复核：单根判定的两个漏洞（已修）
------------------------------------------
`check_single_root` 第一版只对 `Event::Start` 计根，于是：
- 自闭合根 `<a/>` 走 `Event::Empty`，`roots` 始终为 0 → **合法的 XML 被误拒**；
- 根之后再出现的 `<extra/>` 同样走 `Event::Empty` → **第二个根被漏掉**。

现在：`Empty` 在 depth==0 时计一个根并把 `closed` 置真，根后再遇到 `Start`/`Empty` 一律报「多个根」；
文本与 CDATA 在根闭合后只要含非空白字符就报错；最后再检查 `roots==1`、`depth==0`、`closed`。

边界单测（`xlsx::gate_tests`，2 个测试，10 组合）：

    # 应通过
    <a></a> | <a/> | <a><b/></a> | "  <a>t</a>  " | <a></a><!--注释--> | <?xml …?><a/>
    # 必须拒绝
    "" | "   " | <a> | <a></a><b></b> | <a/><b/> | <a></a>text | <a></a><extra/> | <a></a><![CDATA[x]]> | </a>
