一、缺陷（原始失败样本，先复现后修）
----------------------------------
1) 模态对话框背后仍然响应应用级快捷键
   app.hf_dlg = true（页眉和页脚，ui_kit::window 画的模态对话框），跑一帧让对话框真正出现，
   再注入 Ctrl+N：
     assertion `left == right` failed: 模态对话框打开时 Ctrl+N 不得在背后新建文档
       left: 2     right: 1
   即对话框开着时又新建了一个标签（文档在对话框背后被换掉）。

2) 单元格编辑中 Ctrl+P 既没提交草稿也没丢弃，草稿悬空
   A1 输入 "42"（未提交）→ Ctrl+P：
     assertion failed: app.editing.is_none()
   预览打开了，但 42 还挂在编辑缓冲里，既不落格也不参与预览。

3) 开始页（没有文档）时的应用级快捷键此前完全不存在
   update() 里只有 `!show_start` 分支才调 handle_keys，开始页 Ctrl+N / Ctrl+O 都是死键。
   证据：4a24506 的 main.rs 22388 附近
     if self.show_start { self.home_page(ui); } else { if !self.backstage { self.handle_keys(ctx); } ... }

4) 快速访问工具栏（标题栏 QAT）自己算了一套可用性
   旧代码：`(Icon::Save, "保存（Ctrl+S）", true)` —— 保存永远点亮，
   撤销/重做用内联 can_undo()/can_redo()，tooltip 里的快捷键是手写字符串。
   与命令表、功能区、快捷键各说各话。

二、实现
--------
新增 crates/app/src/command.rs（命令表，唯一登记处）：
  Command { action, label, key, shift, on_start, in_cell_edit, enabled }
  COMMANDS = FileSave(Ctrl+S) / FileSaveAs(Ctrl+Shift+S) / FileOpen(Ctrl+O) /
             NewTab(Ctrl+N) / PrintPreview(Ctrl+P) / Undo(Ctrl+Z) / Redo(Ctrl+Y)
  - command_enabled(action)：按钮灰态与快捷键共用的唯一谓词
  - disabled_hint(action)：不可用原因，tooltip 与状态栏同源
  - command_exec(action, ctx)：功能区、QAT、标签条 +、开始页、快捷键共用的唯一执行函数
  - handle_command_keys(ctx)：按键分发，只认表

键盘优先级（写进模块文档，并被测试锁定）：
  Dialog（ui_kit 模态）> CellEdit > Start > Grid
  - Dialog：应用级命令一律不执行；标记由 ui_kit::Dlg::show 每帧打点
    （ui_kit::take_dialog_shown，读一次即清），不枚举 50 个对话框字段，新增对话框自动纳入
  - CellEdit：文档/外壳类命令先提交有效编辑再执行（校验不通过则停下），撤销/重做让给 TextEdit
  - Start：只有新建/打开可用，保存/打印不可用
  - 名称框/查找框等非模态 TextEdit 不算一层：egui TextEdit 只吃文本键与方向键，Ctrl 组合归应用（与 Excel 一致）

接线：
  main.rs  update()：!backstage 时先 handle_command_keys（开始页也跑），再走原有网格按键
           handle_keys：删掉 Ctrl+S/O/N/P 与 Ctrl+Z/Y 的自写分支
           QAT：可用性/tooltip/执行改为 command_enabled / cmd.tip() / command_exec
           doc_tabs 的 + 与开始页入口：改为 command_exec("NewTab"/"FileOpen")
  ribbon/actions.rs  ctl_state：FileSave/FileSaveAs/FileOpen/NewTab/三个打印预览按钮/Undo/Redo
                     的 enabled 取命令表；不可用时 tooltip 追加原因
                     ribbon_action：进门先 command_exec，登记命令只有一份实现
  ribbon/ui.rs       tip_of：登记命令的 tooltip 自动带 "(Ctrl+S)"，不再手写快捷键字符串
