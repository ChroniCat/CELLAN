QA-03.1 复核补正：隔离测试自身的竞态，与「并行 GREEN」的真实退出码
====================================================================
日期：2026-11-12 UTC+08   环境：source scripts/audit_env.sh <标签>

一、复核指出的问题（逐条）
--------------------------
1. `isolates_temp_and_restores_after_drop` 把 TEMP/TMP/LOCALAPPDATA 写成哨兵值后
   **先释放 ENV_LOCK，再 TestEnv::new 重新加锁**——中间有窗口，别的测试线程可以插进来。
   Drop 之后又在锁外读环境做断言，同理会读到别人的值。`clears_inherited_probe_vars…` 一样。
2. 该用例只验证「哨兵被恢复」，**没有恢复测试入口的原值**：跑完这个测试，进程的 TEMP
   就永久停在哨兵目录上，后面的测试全受影响。
3. 旧证据里的并行结果是 `error: test failed`，串行 139 通过不能替代并行通过。

二、根因（两层）
----------------
第一层是显式的：锁外读、锁外写。
第二层更隐蔽，也是最难查的：`TestEnv` 的根目录原来是
`std::env::temp_dir()/sheets-native-tests`。并行时 A 测试把 TEMP 换成自己的根，
B 测试这时构造 TestEnv，就会把根**嵌套到 A 的根里面**；A 一 Drop，B 的目录连同文件
一起被删——这解释了两个「莫名 NotFound / unwrap None」的失败
（`session_lock::tests::write_then_read_roundtrip`、`files::tests::filter_matches_loaded_subtree`）。
换句话：只要根目录跟着进程环境走，并行就永远不可能稳定。

三、改动
--------
1. `TestEnv::building(lock, tag)`：接受调用方已持有的 `ENV_LOCK`，
   「先锁 → 再写哨兵 → 再构造」中间没有放锁窗口。
2. `EnvTxn`（测试内 RAII 事务）：`begin()` 在**锁内**保存原值；`env()` 把守卫和原值一起
   交给 `TestEnv`；`TestEnv::extra` 在 Drop 时把入口原值写回（顺序是「先 saved 后 extra」，
   反了就会把进程留在哨兵路径上）。`EnvTxn` 自己也实现 Drop，断言 panic 早退也能还原。
3. `TestEnv::entry_value(key)`：测试要核对「Drop 后是否还原」，必须用锁内取得的快照，
   不能在锁外自己读。
4. 根目录改成**与进程环境无关**的 `<repo>/target/test-tmp`，用 `parent()` 逐级上退，
   不写 `../`（带 `..` 的路径与 `std::env::temp_dir()` 的规范路径字节不同，比较会假失败）。
5. 顺序上先还原构造时看到的值（可能是测试自己写的哨兵），最后用 `extra` 覆盖成入口原值。

四、验证（全部真实输出）
------------------------
并行（cargo 默认线程数，未加 --test-threads）连跑两轮：

    $ cargo test -p app --no-default-features --features glow --bin app

    EXIT=0
    test result: ok. 139 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.79s
    EXIT=0

修复前的同一命令（默认并行）：

    test result: FAILED. 136 passed; 3 failed; 0 ignored
    failures:
        files::tests::filter_matches_loaded_subtree           (panicked: Option::unwrap on None)

        test_env::tests::isolates_temp_and_restores_after_drop (TEMP 还原成了别人的临时根)

完整的 3 失败 → 1 失败 → 0 失败三阶段都保留在会话产物里：
- 根目录改成稳定路径之前：136/3

  `...sheets-native-tests/29424-2-ui02-ctrl-o`，正是别人测试的根）

五、仍然存在的边界
------------------
- 进程级环境变量本身仍是全局状态：`TestEnv` 靠 `ENV_LOCK` 串行化，
  **任何绕过 TestEnv 直接 set_var 的测试都会重新引入竞态**。用 grep 确认当前没有
  （`recent.rs` 里的 set_var 已删除，只留注释）。
- `ignored` 的 8 个 GUI 用例仍依赖 `tests/test-work` 外部夹具，未逐个自建夹具。
- 真实多机 LAN 协作未验证；这里的「多参与者」是同机两个进程 + 回环。
