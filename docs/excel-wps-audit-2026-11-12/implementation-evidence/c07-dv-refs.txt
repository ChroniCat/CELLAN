# C07.1 命名列表 / 跨表区域 / 公式阈值

日期：2026-11-13 21:20 CST
范围：`crates/core/src/dv.rs`、`crates/app/src/main.rs` 的数据验证入口、合成夹具 `crates/core/tests/fixtures/c07/refs.xlsx`。

## 本轮按监督四点修复

1. **范围锚点**：数据验证公式的基准是规则范围左上角，不是当前格绝对坐标。
   新增 `dv::range_anchor(dv, r, c)`；`commit_edit` 和 `compute_invalid` 调
   `shift_formula(f, r - anchor.r, c - anchor.c)`。C2:C3 的 `>=$A1` 在 C2 比较 A1，
   C3 比较 A2，不再把 C2 的 15 错比 A2=20 拒绝。`50993` 只把 `=A1` 改成 `=$A$1`
   并不能证明相对行闭合，本轮用混合引用 `=$A1` 的首格/下一格回归覆盖。
2. **坏阈值不再伪装成 1**：生产闭包解析失败时不再返回 `Bool(true)`（经
   `bound_value` 会变成 1，`>=1` 会放过 2），改为 `FValue::Error(Value)`，
   `bound_value` 保持 `None`，校验失败。应用同时记录
   `数据验证配置无效：公式阈值无法解析：...`，与普通“候选值非法”区分。
   列表来源无法解析也会显示 `数据验证配置无效：列表来源无法解析：...`。
3. **只对 List 解析列表**：`validate_wb` 仅在 `DvKind::List` 调用
   `list_items_wb`，数值/日期阈值走 `bound_value` 公式求值，不再把
   `SUMPRODUCT(...)` 之类的长函数先当列字母。`parse_a1` 的列/行累计改用
   `checked_mul/checked_add` 并做 16384/1048576 上界检查，超长英文名称返回
   `None` 而不是 debug 溢出 panic。
4. **名称解析**：同名时本表级优先于工作簿级；`'O''Brien'` 单引号转义解码为
   `O'Brien`；`FILTER(...)` 等动态公式来源返回 `None`，不会被替换成数组字面量。
