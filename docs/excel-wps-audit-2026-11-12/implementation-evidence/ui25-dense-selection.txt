# UI-25 百万行密集选区（状态栏分帧统计）

日期：2026-11-17　构建：release / glow

## 1. 这轮补的是哪条 not_done

台账原文：「百万行密集选区分帧耗时未压测（仅百万行稀疏表）」。
本轮用一张 **1000×1000 = 1,000,000 格**的真实工作簿（`work/probe/qa07/values1m.xlsx`，
4.1MB，数值 0..999999），把选区拉到整列 1,000,000 行，量状态栏统计的帧耗时与结果。

## 2. 结果

| 指标 | 数值 |
|---|---|
| 选区 | `A1:A1000000`（`rects=[(0,0,999999,0)]`） |
| 状态栏文本 | `平均值: 496.515    计数: 1000    求和: 496515` |
| update() p50 | **0.91 ms** |
| update() p95 | **1.72 ms** |
| update() max | 155.36 ms（装载那一帧） |
| 与同步口径对照 | 1k 行选区（走同步分支）同样输出 `平均值: 496.515 计数: 1000 求和: 496515` |

分帧参数是 200,000 值/帧；1M 行选区里实际有值 1000 个，一帧内就处理完，其余帧完全不做事。
即使把有值行加满，也按 20 万/帧切分，单帧不会超过一次 20 万次遍历。

## 3. 顺带抓到的真实缺陷（已修）

**症状**：任何 `area > 50_000` 的选区，状态栏统计**永远是空**（连「计算中…」都只闪一帧）。

**定位过程**（`SC_STAT_DBG` 逐帧打印，日志 `work/probe/qa07/statdbg*.log`）：

```
[stat] frame=0 mask=11 area=1000000 job=Some((0, 0)) stat="计算中…"
[stat] frame=1 mask=11 area=1000000 job=Some((0, 0)) stat=""
```

`job.vals.len() == 0`，进一步打印 `sheet.get(0,0)`：

```
[collect-pre] a1=None b1=None iter_cells=0
```

**根因**：工作簿是异步装载的。统计任务在「文件还没装完」的那几帧里就按当前选区建好了，
key 只有 `(sheet_idx, doc_gen, rects, mask)`；装载完成后 `doc_gen` 不变、选区不变，
于是任务永远被判「新鲜」，永远不会用装好的数据重建 → 空统计。

**修法**：把 `wb_epoch` 加进 key（与 UI-24.2 后台重算结果加 `doc_gen` 是同一类修复）：

```rust
key: (usize, u64, u64, Vec<(u32,u32,u32,u32)>, u8)  // sheet, doc_gen, wb_epoch, rects, mask
```

**回归用例**：`large_selection_stats_are_not_empty` —— 直接对 values1m.xlsx 的
`A1:A1000000` 调 `collect_stats_values`，断言非空、`计数: 1000`、且同步路径
（`status_stats_rects`）与异步累加器（`StatsAcc::text`）**逐字符一致**。

另外试过把 `rows.size(r) <= 0.0` 这个过滤删掉，结果打断了既有的
`status_stats_cover_multi_rect_filter_and_sparse_edges`（该用例用行高 0 表示隐藏行），
说明行高 0 在本项目里就是「按隐藏处理」的口径，已还原并保留注释。
