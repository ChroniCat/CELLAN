QA-04.1 原生编辑/快捷键/焦点 —— 本机能做到哪、卡在哪
================================================================================
日期：2026-11-16

一、结论先说
------------
- **修掉的真实缺陷**：Ctrl+S / Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z 此前完全没绑键。
  `grep "Key::Z"` 只命中自动化按键解析，`grep "Key::S"` 只命中同一个解析函数；
  功能区和快速访问能点，键盘按了没反应。已在 `handle_file_shortcuts` 里补齐，
  并加了真实 egui 事件回归 `ctrl_z_and_ctrl_y_drive_undo_and_redo`。
- **能用真实 Windows 输入验证的**：F2 进入编辑、Esc 取消、Enter 提交并下移、
  方向键导航（全部走 `PostMessage(WM_KEYDOWN)` → winit 事件路径，不是 SC_* 环境变量）。
- **本机做不到的**：文字键入、带修饰键的组合键、鼠标点击。原因是 Hermes 所在的
  Windows 会话没有可交互桌面（`GetForegroundWindow() = 0`），三条注入路径全部失效：
  1. `SendInput`（真实桌面注入）——没有前台窗口，静默失败；
  2. `WM_CHAR` / `WM_IME_CHAR`——egui 的编辑缓冲没有变化（实测 buf 始终是 `seed`）；
  3. 修饰键——`Ctrl+V` 不粘贴、`Ctrl+S` 不保存，winit 取的是真实键盘状态而不是消息参数。

二、原生键盘实测（可重跑）
--------------------------
脚本：`work/probe/qa04/scenario_nav.ps1`（依赖 `win_input.ps1`）

```
fg=0 active=A1，seed，已选中
edit-node-after-F2: seed                 ← 编辑栏出现 Edit 节点，值=seed（进入编辑）
edit-node-after-ESC: <missing>           ← Esc 后节点消失（编辑取消）
after-enter: 选区 A1:A1，活动单元格 A1 -> 选区 A2:A2，活动单元格 A2
after-down-down-right: 选区 B4:B4，活动单元格 B4
```

注：`fg=0` 是 `GetForegroundWindow()` 的返回值，即当前会话没有前台窗口；
这是 SendInput 失效的直接证据，也是本切片无法完全按验收条款跑的原因。

三、三条注入路径的失败证据
--------------------------
| 路径 | 做法 | 结果 |
|---|---|---|
| SendInput | `keybd_event` + `SetForegroundWindow` | 焦点始终 0，F2 无反应 |
| WM_CHAR | `PostMessage(hwnd, 0x0102, ch, 1)` | `编辑栏` 值保持 `seed` |
| WM_IME_CHAR | `PostMessage(hwnd, 0x0286, ch, 1)` | 同上 |
| WM_KEYDOWN + 修饰键 | 先发 Ctrl down 再发 V/S | 不粘贴、不保存；无修饰键的 F2/Enter/Esc 正常 |
| WM_LBUTTONDOWN | 按 UIA 矩形换算客户区坐标点击 B2 | 选区不动（winit 用真实光标位置，不用消息坐标） |

四、修复：文件级快捷键
----------------------
```rust
fn handle_file_shortcuts(&mut self, ctx: &egui::Context) -> bool {
    if self.editing.is_some() { return false; }   // 编辑态交给 TextEdit 文本撤销
    // Ctrl+S 保存（Shift 另存为）/ Ctrl+Z 撤销 / Ctrl+Y 重做（Shift+Z 也重做）
}
```
回归测试 `ctrl_z_and_ctrl_y_drive_undo_and_redo`：写入 7 → Ctrl+Z 撤销 →
Ctrl+Y 重做 → Ctrl+Z 再 Ctrl+Shift+Z 重做，全部断言通过。
