UI-24.1 模态焦点 / 默认按钮 / 关闭恢复
================================================================================
日期：2026-11-16

一、要求（task-index.md UI-24.1）
-------------------------------
「模态焦点/默认按钮/关闭恢复。完成后交付该行为的失败→通过证据。」

二、改了什么
------------
1. `ui_kit::Dlg::show`
   - 打开第一帧记住原焦点（`id.with("focus_before")` 存 egui::Id），
     关闭时 `request_focus` 还回去。
   - 每帧在**帧末**调 `memory.set_modal_layer(对话框层)`：egui 用上一帧的
     `top_modal_layer` 判 `allows_interaction`，所以必须在帧末设置、下一帧生效。
   - **关闭这一帧把模态层降回 `LayerId::background()`**，否则下一帧背景控件
     仍被判「被模态挡住」，`create_widget` 会 `surrender_focus`，把刚还回去的焦点又清掉。
2. `ui_kit::drag_only_sense()`：只拖动、不参与 Tab 焦点。
   用于标题栏、缩放手柄、模态遮挡层。
3. `primary_button` 的默认按钮语义保持并加测试：无焦点时 Enter = 点击；
   输入框有焦点时 Enter 归输入框。

三、失败 → 通过（本轮真实跑出来的）
----------------------------------
第一版只加了 `set_modal_layer`，测试输出：
```
panicked: Tab 之后焦点没有进对话框：["bg"]（模态焦点没有锁住）
```
查出两处真实原因（都不是「测试写错了」）：
- 模态遮挡层用的是 `Sense::click_and_drag()`，自带 FOCUSABLE，Tab 第一站停在它上面；
- 标题栏 `allocate_exact_size(..., Sense::click_and_drag())` 同样可聚焦，
  于是 Tab 在「遮挡层 → 标题栏 → 关闭按钮」里打转，**永远到不了对话框内容**。
  去掉这两处的 FOCUSABLE 后，第二次断言仍然失败：
```
panicked: Tab 循环 6 步都没到「确定」：[]（对话框内容键盘不可达）
```
  因为关闭按钮之后焦点还被送到遮挡层，直到遮挡层不可聚焦才走到「确定」；
- 最后一条失败是关闭后焦点没还回去：
```
panicked: 关闭后焦点没有回到触发控件：[]
```
  根因就是上面第 1 条的「关闭帧仍在设模态层」，背景按钮下一帧执行
  `surrender_focus` 把焦点清掉。

现在的测试（egui 真实 `Context` + 真实 `Event::Key(Tab/Escape)`，不是直接改内存状态）：
```
modal_dialog_traps_tab_focus_and_restores_it_on_escape ... ok
default_button_answers_enter_only_when_no_field_has_focus ... ok
```
断言内容：
1. 第一帧背景按钮拿焦点；
2. Tab 后焦点必须离开背景，且不落在对话框以外的任何控件上；
3. 继续 Tab，最多 6 步必须命中对话框里的「确定」（内容键盘可达）；
4. Esc 关闭对话框，`open == false`；
5. 再跑一帧，焦点回到背景按钮。

四、边界（不要读过头）
----------------------
- **没有用物理键盘/真实输入法在 GUI 里按过 Tab**（RDP 会话无法做键盘注入），
  证据是 egui 真实 Context 的事件循环测试 + 代码里 `set_modal_layer` 的实际调用点。
- Shift+Tab 反向循环没有单独断言（egui 的 Previous 走 `id_next_frame`，逻辑同源但未测）。
- 「默认按钮」只覆盖 `primary_button` 这一种；功能区/工具栏没有默认按钮概念。
- 对话框内容里若有 `ScrollArea`，Tab 不会滚到视口外的控件（egui 自身行为，未处理）。

## 补充（2026-11-17）：反向 Tab / 默认按钮 / 焦点滚动

原 not_done 四条里三条已收口，第四条仍是环境阻塞。

### 1. Shift+Tab 反向循环（新用例）
`shift_tab_cycles_backwards_inside_modal_and_never_escapes`：
Tab 前进到「确定」→ Shift+Tab 必退到对话框内另一个控件（不回背景）→ 再 Shift+Tab 一圈回到「确定」。
实测坑：egui 的焦点迁移排在**下一帧**（按 Shift+Tab 的那一帧仍报旧焦点），
所以断言必须「先跑按键帧 → 清空记录 → 再跑一帧看落到哪」。首版按同帧断言会误判成「焦点没动」。

### 2. 默认按钮覆盖到全部对话框主按钮
`ui_kit::primary_button` 是唯一实现「Enter = 默认按钮」的地方（且要求没有控件持有焦点、
没有弹出层）。扫出并修掉 3 处裸按钮：
- 移动或复制工作表（确定/取消原来用 `ui.button`，也没有 footer）
- 函数向导（同上）
- 排序/分列（「执行」）
新增源码级用例 `every_dialog_primary_action_uses_the_default_button_helper`：
扫 `main.rs` 里所有 `if ui.button("确定"/"执行"/"应用"/"完成"/"下一步"/"导入")`，
命中即失败；`toolbar_cf_items` 里的行内「应用」是菜单项，显式排除。

### 3. 对话框内 Tab 到视口外控件自动滚动
`ui_kit::window` 的滚动分支里，每帧检查当前焦点控件的矩形，若不在 `clip_rect` 内就
`scroll_to_rect(…, Align::Center)`。
用例 `tabbing_into_scrolled_dialog_scrolls_the_focused_button_into_view`：360×200 的对话框塞 40 个按钮，
Tab 走到底。**反向验证过**：把滚动那行改成 `false &&` 后用例失败
（`last [[236.0 1120.0] - [287.0 1140.0]]` 在视口 `[[0 220] - [800 426]]` 之外），改回来通过。
