C01.1 错误类型与文本错误区分
=============================
日期：2026-11-13 UTC+08   对标：core-requirements.md C01（P0，切片 C01.1）

一、原始缺陷
------------
| 位置 | 问题 |
|---|---|
| `formula/mod.rs:2195 from_fvalue` | `FValue::Error(e) => V::Text(e.text())` —— 公式算出的错误落成**文本** |
| `model.rs:18 enum Value` | 没有错误分支，模型层面无法区分「错误」和「长得像错误的文本」 |
| `xlsx.rs:74 data_to_value` | `Data::Error(e) => Value::Text(format!("#{:?}", e))` —— 用 Debug 拼字符串，`#Div0` 这种写法根本不是 Excel 文本 |
| `formula/mod.rs:2328 has_spills` | 只认 `Value::Text("#SPILL!")`，错误变类型后增量重算不再判定需要全量修复 |

后果：`=1/0` 的结果与用户手打的 `#DIV/0!` 在模型里完全相同，
增量重算把它当文本缓存，IFERROR 抓不到，SUM 也不会传播。

二、改动
--------
1. `Value::Error(ErrKind)`（`model.rs`）。`ErrKind` 复用 `formula::value::ErrKind`，
   含 Null/Div0/Value/Ref/Name/Num/Na/Circular/Spill 九种；`Value::display()` 输出 `e.text()`。
2. `to_fvalue` / `from_fvalue` 双向保类型（`V::Error(e) => FValue::Error(*e)` 及其反向）。
3. `ErrKind::from_text`：从 `#DIV/0!` 文本还原种类，读文件/读修订日志共用。
4. 所有 `match Value` 的穷举点补齐（编译器逐个指出，共 9 处）：
   - `scenarios::value_text`：方案存的是字符串，错误按显示文本存；
   - `sync::ValueWire`：新增 `Error(String)` 变体，**不能被当成 Text 同步过去**；
   - `sort_filter::key_of`：错误排在最后（数字 < 文本 < 布尔 < 错误）；
   - `revision::Snap`：新增类型标记 `"x"`，`to_cell` 用 `from_text` 还原；
   - `xlinks::cell_xml`：外链缓存写 `t="e"`；
   - `xls_write`：`cached_value` 与 BOOLERR 记录用 BIFF 错误码
     （0x00 #NULL!、0x07 #DIV/0!、0x0F #VALUE!、0x17 #REF!、0x1D #NAME?、0x24 #NUM!、0x2A #N/A，
     `#SPILL!` BIFF8 无定义，落成 #VALUE!）；
   - `xlsx` 读：`calamine::CellErrorType` → `ErrKind` 一一映射（不再 Debug 拼串）；
   - `xlsx` 写：错误值走 `set_formula_result_error`，落成 `t="e"`；
   - `formula::recalc_dirty::has_spills`：认 `Value::Error(Spill)`，同时兼容旧的 `Text("#SPILL!")`。

三、测试（`crates/core/tests/error_values.rs`，8 项）
---------------------------------------------------
| 用例 | 断言 |
|---|---|
| `a_computed_error_is_an_error_value_not_text` | `=1/0` 是 `Value::Error(Div0)`，显示 `#DIV/0!` |
| `typed_text_that_looks_like_an_error_stays_text` | 手打 `#DIV/0!`/`'#N/A` 仍是文本；文本不被 IFERROR 吞，真错误被吞 |
| `all_traditional_errors_keep_their_kind` | 七种传统错误逐个核对类型与显示文本 |
| `iferror_catches_a_real_error` | `IFERROR(A1,"兜底")` = 兜底 |
| `sum_propagates_a_real_error_instead_of_skipping_it` | `SUM(A1:A3)` = `#DIV/0!` |
| `a_reference_to_the_same_sheet_keeps_the_error_type` | `=数据!A1&""` 仍是错误（**同一张表**，不是跨表；跨表待 C01.3） |
| `full_recalc_keeps_the_error_type` | 调 `recalc_all` 全量重算后仍是 `Error(Div0)`；**没有**验证 `recalc_dirty` 增量路径（C01.3） |
| `save_and_reload_keep_the_error_type` | 公式错误与静态错误存盘后仍是 `Error(..)`，文本 `#DIV/0!` 仍是 Text |

RED（模型还没有 `Value::Error` 时）编译失败，逐条 `no variant named Error`；
补上变体但保留旧 `from_fvalue` 时，前 7 项都会在 `assert_eq!(Value::Error(..), Text(".."))` 处失败。

四、全量回归暴露的真问题
------------------------
第一轮全量 core 有 3 个失败，全部是**旧模型的断言**或**依赖文本判定的逻辑**：

1. `array_functions::spill_blocked_by_existing_data`
   `assert_eq!(value, Value::Text("#SPILL!"))` —— 旧错误模型的产物。
   改成 `Value::Error(ErrKind::Spill)` + `display() == "#SPILL!"`。
2. `formula_parity::circular_reference_is_caught`
   `assert_eq!(value, Value::Text("#REF!"))` —— 同上。
   改成 `Value::Error(ErrKind::Circular)` + 显示 `#REF!`。
3. `recalc_correctness::blocked_array_retries_when_obstruction_is_cleared`
   **不是断言问题，是真 bug**：`has_spills` 只认文本 `#SPILL!`，
   错误变类型后增量重算判定「没有溢出」，清掉障碍物后不再重算，A2 缓存停留在 Empty。
   修 `has_spills` 后通过。

前两条是把断言改到**新模型**（要求原文就写明错误要成为类型），不是为了让失败消失而放松断言；
第三条是本次改动引入的真实回归，已修在实现里而不是测试里。

四之二、命名更正（00:19 复核）
------------------------------
原先两条用例名分别叫 `cross_sheet_reference_keeps_the_error_type` 与
`incremental_recalc_keeps_the_error_type`，但实际覆盖是「同一张表的引用」与
「recalc_all 全量重算」，名字暗示了没验证的东西。已按实际覆盖改名，并在上表写清。
