# UI-14.3 证据：General（常规）按列宽显示（2026-11-17）

## 原缺口

长整数用 General 时本程序永远显示完整数字（例如 123456789012345），
Excel 在默认列宽下显示 `1.23E+14`，AutoFit 也按科学计数文本量宽。
根因：`style::format_value` 的 General 分支直接 `Value::display()`，没有列宽概念。

## Excel 实测（Excel 16.0 Build 20326，`work/probe/general_probe.ps1`）

列宽 40（宽列）与 8.43（默认）两档，同一批值：

| 值 | 宽列 40 | 默认 8.43 |
|---|---|---|
| 1234567890 | 1234567890 | 1.23E+09 |
| 12345678901 | 12345678901 | 1.23E+10 |
| 123456789012 | 1.23457E+11 | 1.23E+11 |
| 1234.5678 | 1234.5678 | 1234.568 |
| 0.000012345 | 0.000012345 | 1.23E-05 |
| 1.23456789012 | 1.23456789 | 1.234568 |
| -123456789012 | -1.23457E+11 | -1.2E+11 |
| 100000000000 | 1E+11 | 1E+11 |
| 99999999999 | 99999999999 | 1E+11 |

结论：

- 宽列的精度上限是 **11 个字符**（尾零去掉；负号在宽列不占这 11 格，
  窄列连负号一起算总宽）；
- 整数 11 位以内原样，12 位起科学计数（最多 5 位小数）；
- 小数按可用宽度四舍五入去尾零；固定小数写不出 3 位有效数字时改科学计数；
- `99999999999` 在窄列四舍五入后进位成 `1E+11`。

## 实现

`crates/core/src/style.rs`：

- 新增 `general_display(n, cap)`：按上述规则，cap 为可用字符数；
- `format_value` 的 General 分支改用 `general_display(n, 11)`；
- 新增 `format_value_fit(v, fmt, cap)`：只有 General 受 cap 影响，
  显式格式（`0.00`、日期等）逐字节不变；
- 网格绘制用单元格实际宽度反算 cap：
  `((rect.width()/zoom − 5)/8).floor()`，默认 8.43 列宽 → 8；
- AutoFit 仍走 `format_value_in`，因此量宽的是科学计数后的文本，而不是完整数字；
- 打印/PDF 走 `display::view_at_value_fit`，cap 由打印列宽（含合并宽度）反算，
  避免「屏幕上 1.23E+09、打印出来 1234567890」的两套显示。

打印回归：`crates/core/tests/ui143_general_print.rs`
`print_general_respects_column_width`——默认列宽 10/11 位整数输出科学计数，
宽列 11 位整数原样。

## 测试

固定向量测试 `style::tests::general_matches_excel_width_measurements`
覆盖上表宽/窄 20 组；`general_fit_is_ignored_for_explicit_formats` 保证
`0.00` 等格式不被列宽改写。

无界面 AutoFit 实跑（`SC_AUTOFIT=c:0`，值 123456789012345）：

```
[autofit] r0 txt="1.23457E+14" len=11 text_px=77.5 chars=10.65
列0 72 -> 100 px
```

即量宽用的是 11 字符科学计数文本（Excel 同值基准 10.63 字符）。
