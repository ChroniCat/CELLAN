QA-04.3 多文档 / 后台任务归属
================================================================================
日期：2026-11-16

一、结论
--------
多文档的「值 / 选区 / 滚动 / 脏标记 / 撤销历史 / 后台保存 / 后台重算」归属，
已用 5 条真实代码路径的回归验证：**4 条通过、1 条暴露真缺陷并修掉**。

真缺陷：后台「重算全部」的结果只按 `wb_epoch` 认领，而 `wb_epoch` 是每个文档
各自计数 —— A 文档发起时的 epoch 可能恰好等于 B 文档切回来后的 epoch，导致
A 的重算结果覆盖 B 的工作簿。修法两条：
1. `OpenMsg::RecalcedWb` 增加 `doc_gen`，接收侧 `epoch == wb_epoch && doc_gen == doc_gen` 双条件；
2. 切标签 / 开新标签前主动置位 `tasks.recalc_cancel`，不等它回来。

二、回归测试（`crates/app/src/edit_regression_tests.rs`）
----------------------------------------------------------
| 测试 | 验证内容 | 结果 |
|---|---|---|
| `switching_tabs_keeps_values_selection_scroll_and_dirty_per_document` | doc1 写值 + 选区 (3,2) + 滚动 240 + 脏；开新标签后是空白、A1、滚动 0；来回切各自复原 | pass |
| `undo_history_belongs_to_its_own_document` | doc2 撤销不影响 doc1；doc1 自己的编辑在；切回 doc2 重做仍生效 | pass |
| `background_save_finishes_in_its_own_tab_after_switching` | doc1 后台保存期间切走并编辑 doc2；保存完成后 doc1 文件里是 `saved1`、脏标记清掉，doc2 仍脏且内容为 `dirty2` | pass |
| `switching_tabs_cancels_inflight_recalc_and_keeps_other_doc_intact` | 2 万行公式链发起重算后立刻开新标签：旧文档的取消标志被置位，新文档写入的值和空公式列都不被旧结果污染 | pass |
| `recalc_result_from_another_document_is_discarded_even_if_epoch_matches` | 伪造 `epoch` 相同、`doc_gen` 属于另一个文档的重算结果 → 被丢弃；同一消息把 `doc_gen` 换成当前文档 → 被接受 | pass |

最后一条是关键反例：它同时证明了「拦截理由是归属」而不是「这个分支永远拒绝」。

三、改了什么
------------
```rust
enum OpenMsg {
    // 之前只有 epoch
    RecalcedWb(Box<Workbook>, Box<Deps>, u64, u64),   // + doc_gen
}

// 接收侧
if epoch == self.wb_epoch && doc_gen == self.doc_gen { /* 采纳 */ }

// 切标签 / 开新标签
fn cancel_bg_recalc_on_switch(&mut self) {
    if let Some(c) = self.tasks.recalc_cancel.as_ref() {
        c.store(true, Ordering::Relaxed);
        self.status = "切换文档，已取消未完成的重算".into();
    }
}
```

四、边界（没验到的）
--------------------
- **切标签的动作本身**走的是 `switch_tab`/`open_in_new_tab` API，不是真人点标签：
  文档标签条只在已有多个标签时出现，而打开第二个文档要走 rfd 文件对话框；
  本机无交互桌面（`GetForegroundWindow()=0`），点击与 rfd 都无法驱动。
  已实测：单文档时 UIA 树里没有文档 TabItem，只有工作表 `TabItem Sheet1`。
- 未测「两个文档都很大时来回切」的耗时；未测「保存中关标签」的二次确认路径
  （`confirm_close_target` 有代码，没有对应断言）。
- 未测跨文档复制粘贴（归 QA-04.1 ⑤⑥，被原生输入阻塞）。
