# XLS 导出兼容保护（C11 辅助安全网）

状态：XLS 导出拒绝保护已验收；这是**导出格式保护**，不能替代 C11 原始
“输入/重算不支持语法时保留公式+缓存+可见诊断”的要求。后者见
`c11-unsupported-cache.txt`；父项 C11 仍未验收。
日期：2026-11-13。

## 实现

- `xls_write::write` 在创建输出前编译所有工作表公式；`.xls` 的 BIFF
  不能表达 `@` 隐式交集、`#` 动态数组等时返回错误，并附加：
  `兼容提示：.xls 不能完整保存该公式/引用组合（工作表 Data）...`
- `xlsx::save_atomic` 先写临时文件，失败不替换目标；核心 `xls_write`
  只在全部工作表编译后才写 OLE，因此失败不改目标。
- App `start_save` 失败恢复 `dirty=true`，状态栏显示错误（含兼容提示），
  原工作簿模型里的公式和缓存值不变；用户可另存 `.xlsx`。
- 这不是把不支持公式静默写成首表/错误值；也不会把旧的正确 `.xls`
  覆盖成半成品。

测试断言：

1. 目标 `.xls` 预先写入 `ORIGINAL`，保存失败后字节仍为 `ORIGINAL`；
2. 模型里 `Data!A1` 的 `=@A1`、缓存 7 仍存在；
3. 错误文本包含“兼容提示”和单元格位置；
4. 同一工作簿另存 `.xlsx` 后重新加载，公式 `=@A1` 和缓存 7 仍在；
5. App 层失败保持 dirty，状态栏显示兼容提示。

## 父项 C11 原始要求仍待办

本文件的拒绝保护只证明 `.xls` 输出不会覆盖目标、App 保持 dirty 并提示；
它不证明 C11 输入/重算时对合法但引擎不支持的引用组合保留公式与缓存。
该链独立见 `c11-unsupported-cache.txt`，父项 C11 仍不翻绿。

## 边界

- `.xls` 不能表达的组合仍不能“原样”写入 `.xls`；本实现选择保留源
  模型/目标文件并提示另存，而不是伪造 BIFF 公式。后续若要更强兼容，
  需要单独设计降级公式和回读提示，不能把本条当成已完成。
