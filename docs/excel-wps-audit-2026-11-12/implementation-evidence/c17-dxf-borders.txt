# C17 Dxf 四边边框：逐边保真 + 未建模方向的显式提示

日期：2026-11-14
触发：监督复核指出 `DxfBorder` 只存一份 `style/color`，四边不同时后一条覆盖前一条，
四边被套成同一条；对角/内部边框则被静默丢弃，既不保真也没有提示。

## 修复

`crates/core/src/cf.rs`

```rust
pub struct DxfBorder {
    /// 0=左 1=右 2=上 3=下；`(style, color)`，color 缺省按黑色
    pub sides: [Option<(String, [u8; 3])>; 4],
}
```

- `parse_dxfs` 重写为带 side 状态的解析器：`left/right/top/bottom` 各自建槽，
  随后的 `<color>` 落到对应边；`font/name/b/i/numFmt/fill` 行为不变。
- 新增 `dxfs_unsupported(xml)`：出现带 style 的 `diagonal/vertical/horizontal/start/end/outline`
  时返回 true；`CfSheet.dxf_unsupported` 随表加载置位。
- `CfSheet.unknown_ext` 仍表示 x14 扩展；二者都在条件格式管理窗口顶部给出橙色警告：
  - x14：保存会丢掉扩展；
  - 对角/内部/起止边：保存会丢掉这些边，无法无损编辑。

`crates/core/src/patch.rs::dxf_xml`：按 left/right/top/bottom 分别写
`<left style="…"><color rgb="…"/></left>`，不再复制同一条到四边。

`crates/app/src/main.rs`：条件格式差异边框按边绘制（左/右/上/下各自的线宽与颜色）；
管理窗口显示未建模警告并继续按 priority 排序。

## Excel 对拍

Excel 16.0 自己写出的 CF 边框形状（用于校准）：

```xml
<dxfs count="1"><dxf><border>
  <left style="thin"><color rgb="FFFF0000"/></left>
  <right style="thin"><color rgb="FF0000FF"/></right>
  <top style="thin"><color rgb="FF00FF00"/></top>
  <bottom style="thin"><color rgb="FFFFFF00"/></bottom>
</border></dxf></dxfs>
```

夹具 `crates/core/tests/fixtures/c17/borders.xlsx`
（openpyxl 写四边不同样式：thick/red、thin/blue、medium/green、double/yellow；
另一条规则写对角边框）。本应用 `Ctrl+S` 保存后，Excel COM 读回第一条规则：

```text
edge7  color=255       (红色, left)
edge10 color=16711680  (蓝色, right)
edge8  color=65280     (绿色, top)
edge9  color=65535     (黄色, bottom)
```

四边颜色各自保留；Excel 对 CF 边框的 `LineStyle/Weight` COM 读取在它自己生成的文件上也是空，
所以这里以颜色与 OOXML style 属性为准（XML 见 `dxf_xml_writes_each_side_separately`）。
