# UI-15.2 证据：.xls（BIFF8）工作表保护编码（2026-11-17）

## 缺陷

1. `.xls` 写盘完全没有 PROTECT/PASSWORD 记录——受保护表另存 `.xls` 后保护丢失。
2. `protection::legacy_hash` 算法是错的：先异或再移位、正序遍历、末尾少移一位。
   Excel 的 worksheet verifier 是**倒序**、每步先循环左移再异或，最后再移一位
   并异或长度/0xCE4B。同一口令 `s3cret`：
   - Excel 生成的 `.xls` 的 PASSWORD 记录 = `FF DB`（LE u16 = **0xDBFF**）
   - 旧实现 = `0xC173` → 即便写了记录，Excel 里也解不开，且 OOXML 的
     `sheetProtection password="..."` 同样解不开。
3. `.xls` 读盘忽略 PROTECT(0x0012)/PASSWORD(0x0013)，保护状态读不回来。

## 修正

- `crates/core/src/protection.rs`：`legacy_hash` 按 Excel 口径重写；新增固定向量
  测试（`s3cret` → 0xDBFF）。
- `crates/core/src/xls_write.rs`：工作表流 EOF 前写 PROTECT(`fLocked=1`) 与
  PASSWORD(旧式哈希)。记录位置必须和 Excel 一样靠后；放 DIMENSIONS 后面
  Excel 判“文件有问题”。
- `crates/core/src/xls_read.rs`：`SheetData` 增 protection，解析
  PROTECT/PASSWORD 并落到 `Sheet.protection`；`load()` 一并带出。
- 只写 fLocked；对象/方案保护是另外的 OBJPROTECT/SCENPROTECT 记录，不冒充支持。

## 实测（Excel 16.0 Build 20326）

本程序写 `work/probe/prot.xls`（口令 `s3cret`），Excel COM 打开：

```
A1_text=A1
ProtectContents=True
ProtectDrawingObjects=False
ProtectScenarios=False
unprotect_ok=True          # $ws.Unprotect('s3cret') 后 ProtectContents 变 False
```

反方向，读 Excel 自己生成的受保护 `.xls`：

```
sheet=True legacy=DBFF verify_s3cret=True verify_wrong=False
```

即读写双向都能与 Excel 对上，且口令哈希可验证。
