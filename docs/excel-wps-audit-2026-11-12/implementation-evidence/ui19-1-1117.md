# UI-19.1 证据：10 万项序列下拉的每帧成本（2026-11-17）

## 原缺口

台账 not_done：「10 万项 GUI 滚动计时未做」。代码里下拉已经用
`egui::ScrollArea::show_rows` 只画可视行，但每帧都会：

1. `dv_items()` 重新解析序列来源（可能是公式/命名区域）；
2. 重新分配 10 万个 `String`；
3. 再按搜索词过滤一份新 `Vec`。

项数大时这是每帧 O(10 万) 的重复工作，和滚动本身无关。

## 修正

- `SheetApp` 增 `dv_cache: Vec<String>`；
- 打开下拉时（`dv_open_for_selection`）解析一次并缓存；
- 每帧只做 `filter_dv_items(&dv_cache, &query)`，标签里的总数直接用缓存长度；
- 关闭下拉不清缓存没问题，下次打开会覆盖；来源变化时重新打开即刷新。

## 实测

单测 `dv_filter_100k_items_is_frame_cheap`：10 万个 `项目000000…` 项，
查询串 `"" / "9" / "项目09" / "无匹配"` 各过滤一次，最坏 **13.5ms**
（debug 构建），结果计数校验通过。

真实鼠标滚动 100k 项、逐帧计时仍受本机 RDP/软件 GPU 帧率限制（同一 3 行
文件也会出现 280ms 周期 stall），不把环境帧率当程序性能；该项保持待验收。
