## 2. 修了什么（4 处真实缺陷）

1. **查找函数根本没看通配符**。`functions.rs` 的 VLOOKUP/MATCH/XLOOKUP 只做 `compare()==Equal`，
   `mod.rs` 里还有一条基于哈希索引的快速路径，同样只支持等值。修法：
   - 新增 `wildcard_match_ci(pat, text)`（`*`/`?`/`~`，大小写不敏感）与 `pub(crate) is_wildcard`；
   - 快速路径遇到「文本键含通配符」直接 `call_generic` 落到通用实现，两条路径都要改，只改一条不生效（本轮实际踩到）。
2. **错误值查找键被吞成 #N/A**。Excel 把 `#DIV/0!` 这类错误原样抛出。两条路径都在入口加 `FValue::Error(e) => Err(e)`。
3. **近似匹配遇重复值取错行**。Excel 取最后一个 `<=` 的值；原实现 `Equal => { best=Some(i); break; }` 取第一个。
   通用实现与快速路径都改为 `Equal/Less 都记 best，遇 Greater 才停`。
4. **TEXT 只认第一段**。原实现把整串当格式，`;` 后的段落连字面一起输出（`2024-03-15;@`）。补齐：
   - 顶层 `;` 分段（引号内不切）、`[Red]`/`[$-409]` 类标记剥离；
   - 文本值走第 4 段，`@` 占位替换，引号字面量去引号；
   - 零段/负段选段，负号由该段字面 `-` 提供（对绝对值排版）；
   - `mmm/mmmm/ddd/dddd` 用英文月名/星期名（本机 Excel 的输出就是 `Mar`/`March`/`Fri`/`Friday`）；
   - 没有数字占位符的段（如 `"零"`）按字面输出，不再被当数字格式排成 `0`。

## 3. 结果

```
cargo test -p sheetcore --test qa06_matrix -- --test-threads=2
test result: ok. 2 passed; 0 failed; 124 条矩阵全一致
```

WPS 12.0 仍有两处历史差异（与本次无关，已登记）：`EFFECT`/`NOMINAL` WPS 返回 `#NAME?`；
`TEXT` 的 `[Red]` 四段式 WPS 不报错而 Excel 报 `#VALUE!`（该条已从矩阵剔除，避免把 Excel 自身的
quirk 当成引擎缺陷）。
