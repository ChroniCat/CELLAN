三、抓到的真缺陷（已修）
------------------------
**功能区「更多 ▾」在 760 宽时画到窗口外 11px**（修复前 `max_right = 771 / 760`）。
原因：折叠判断用 `used + w > avail`，只给分组本身留空间，没给「更多 ▾」预留宽度，
最后一个分组塞进去之后剩余空间不足，按钮直接溢出裁切区。
修法：折叠条件改成 `used + w + 60.0 > avail`；并且给「更多」加了兜底——
若剩余宽度连 60pt 都没有（首组就超宽的极端情况），用 `scope_builder` 把按钮
钉在裁切区右侧 56pt 内，绝不画到窗口外。
复测：`更多 ▾` 在 760 宽窗口里 `local x=629..682`，`max_right=734 < 760`。

同时验证「更多」不是摆设——用 UIA `InvokePattern` 真实点击：
```
CLICKED=更多 ▾
Button 单元格 at=848,270,54,24
Button 编辑   at=848,297,54,24
Button 加载项 at=848,324,54,24
```
弹出菜单里能列到被折叠的组。

   状态栏高 22pt、按钮 `add_sized([18,20])`，理论上不该溢出，怀疑是 accesskit
   矩形被交互尺寸/焦点描边撑大。**没有确认是否真的视觉裁切**（vision 服务超时，

2. **编辑栏在非编辑态没有 Edit 节点**：三档都只有 `Edit 名称框 / 字体 / 字号 /

## 补充（2026-11-17）：三条 not_done 收口

### 1. 状态栏缩放控件溢出窗口底边（已修）
UIA 实测（1440×900，`uia_dump.ps1`）：
- 修前：窗口 `rect=401,338,1440,900`（底边 1238），`100%` 按钮 `at=1804,1216,28,24`（底边 **1240**，多 2px）。
- 根因：状态栏面板固定 22px，而按钮走默认 `interact_size.y`（24），垂直居中后上下各顶 1px。
- 修法：状态栏缩放那一行 `ui.spacing_mut().interact_size.y = 18.0`，`100%` 按钮改 `add_sized([44,18])`。
- 修后：窗口 `rect=115,52,1440,900`（底边 952），按钮 `at=1503,933,44,18`（底边 **951**）→ 不再越界。

### 2. 公式栏空闲态在 UIA 里是 Edit（已补）
原来空闲态只是一个 `Label`（文本），UIA 树里没有 Edit 节点，屏幕阅读器读不到当前单元格内容。
现在给这个 Label 显式挂 accesskit `Role::TextInput` + `label="编辑栏"` + `value=<单元格显示文本>`。
UIA 实测（A1 选中）：`Edit 名称框 value=A1` / `Edit 编辑栏 value=00123 at=397,355,37,16`。

### 3. 760 档「搜索框」的真相
功能区**没有**搜索框（代码里只有字体/字号两个输入框和 Ctrl+Q 命令搜索），所以「隐藏后能否从更多到达」
这个前提不成立。命令搜索走 Ctrl+Q 全局浮层（`command_palette`），与窗口宽度无关，760×420 下同样可用；
字体/字号框在 760 档仍可见（UIA：`Edit 字体` / `Edit 字号` 均在树里）。
