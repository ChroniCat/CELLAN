QA-05.1 1440×900 / 1024×768 / 760×420 三档基线
================================================================================
日期：2026-11-16

一、方法
--------
`work/probe/qa05/run_size_probe.ps1` 按尺寸矩阵启动 release app（ppp=1.0），
各自 `SC_SHOT` 落 PNG；再用 `uia_dump.ps1 -Ppp 1.0 -WinW/-WinH` 抓可访问树，
用窗口矩形逐个核对「元素是否落在窗口内、有没有零尺寸节点、功能区最右元素是否被裁」。

三、抓到的真缺陷（已修）
------------------------
**功能区「更多 ▾」在 760 宽时画到窗口外 11px**（修复前 `max_right = 771 / 760`）。
原因：折叠判断用 `used + w > avail`，只给分组本身留空间，没给「更多 ▾」预留宽度，
最后一个分组塞进去之后剩余空间不足，按钮直接溢出裁切区。
修法：折叠条件改成 `used + w + 60.0 > avail`；并且给「更多」加了兜底——
若剩余宽度连 60pt 都没有（首组就超宽的极端情况），用 `scope_builder` 把按钮
钉在裁切区右侧 56pt 内，绝不画到窗口外。
复测：`更多 ▾` 在 760 宽窗口里 `local x=629..682`，`max_right=734 < 760`。

同时验证「更多」不是摆设——用 UIA `InvokePattern` 真实点击：
```
CLICKED=更多 ▾
Button 单元格 at=848,270,54,24
Button 编辑   at=848,297,54,24
Button 加载项 at=848,324,54,24
```
弹出菜单里能列到被折叠的组。

四、未解决的问题（如实登记）
----------------------------
1. **状态栏缩放控件的可访问矩形比窗口底边多 2–5px**：
   `100% +−` 在 760 档 `bottom_overflow = 2/4/5`，1440 档同样约 5px。
   状态栏高 22pt、按钮 `add_sized([18,20])`，理论上不该溢出，怀疑是 accesskit
   矩形被交互尺寸/焦点描边撑大。**没有确认是否真的视觉裁切**（vision 服务超时，
   无法看图判定），所以不写成已修。
2. **编辑栏在非编辑态没有 Edit 节点**：三档都只有 `Edit 名称框 / 字体 / 字号 /
   搜索命令`，公式栏要点进去才有节点（与 UI-24.2 早先记录一致）。
3. **760 档搜索框整体隐藏**，只在标题栏留「更多 ▾」入口；搜索是否能从该入口到达未验。
4. 没有 golden 图基线，只有尺寸/边界/可访问树核对，因此本切片证明的是
   「不崩、不越界、折叠可达」，不是「外观与设计稿一致」。
