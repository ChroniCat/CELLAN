# UI-01 编辑提交链路：单元回归 + 真实窗口

日期：2026-11-13 23:5x CST
基线问题（审计 df48672 记录）：`draw_grid_pane` 用 `self.editing.take()` 拿局部 `ed`，
Enter/Tab 分支直接调 `commit_edit`，而 `commit_edit` 只在 `self.editing.take()` 为 Some 时写入，
导致真实路径输入丢失。当前 HEAD 已由前序工作改为"缓冲唯一所有者 = self.editing"，
本切片把剩余验收补齐并做真实窗口复验。

## 现状核对（代码）

- `commit_edit`（main.rs:7154）只从 `self.editing.take()` 取缓冲；
- 网格编辑器（main.rs:22046 起）用 `self.editing.as_mut()` 借用同一缓冲绘制，不再有局部副本；
- Enter/Tab/Esc、公式栏、点其它格、切工作表、名称框跳转、保存、关窗口都先走同一个提交/取消函数。

## 真实窗口复验

探针：`SC_TYPE`（逐帧注入 Text）与 `SC_KEYSEQ`（逐帧注入按键），都进入运行中应用的
真实帧循环，由同一个 `handle_keys`/`draw_grid_pane`/`commit_edit` 处理。

```text
SC_SEL=0,0 \
SC_TYPE="60:123;210:456" \
SC_KEYSEQ="90:enter,120:up,150:f2,180:ctrl+a,240:tab,300:ctrl+s" \
SC_SHOT_FRAMES=420 SC_SHOT_EXIT=1 ./target/debug/app.exe ui01.xlsx
```

stderr：

```text
[types] frame 60 -> "123"
[keyseq] frame 90 -> enter
[keyseq] frame 120 -> up
[keyseq] frame 150 -> f2
[keyseq] frame 180 -> ctrl+a
[types] frame 210 -> "456"
[keyseq] frame 240 -> tab
[keyseq] frame 300 -> ctrl+s
[save] 已保存 F:/.../ui01.xlsx
```

结果：
- 截图 `ui01-edit-chain.png`：A1 显示 456，名称框 B1，无编辑器，状态栏"单元格模式 就绪"；
- openpyxl 回读保存后的文件：`A1 456`（工作簿里 A2 的说明文字是夹具原有内容）。
