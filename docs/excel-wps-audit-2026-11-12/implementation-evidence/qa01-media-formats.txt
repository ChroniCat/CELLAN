二、这一轮抓到的两个真实缺陷（已修 + 回归）
--------------------------------------------
1) 加载即把 textboxes 标脏 → 保存时用我们的文本框模型重写整个 drawing
   现象：Excel 里的矩形在我们保存后变成「文本框」：`cNvSpPr txBox="1"`、
   `a:off/a:ext` 归零、`xdr:style` 整段消失；Excel 重开 shape.Type 从 1(msoAutoShape)
   变成 17(msoTextBox)，名字也从“Rectangle 3”变成“矩形 3”。
   根因：xlsx::load 里 `sheet.textboxes_dirty = true`，而 textbox::apply 只在 dirty 时跑，
   于是一张只读快照被当成用户改过。
   修：加载后保持 false（只读快照）。drawing 部件随后逐字节保真。
   回归：qa01_media_roundtrip.rs 2 条（dirty 为 false、drawing+image 逐字节一致）。

2) .xlsm 基准另存 .xlsx 后 Excel 拒绝打开
   现象：Excel 报「文件格式或文件扩展名无效」。包结构完整，问题在
   [Content_Types].xml 仍声明 `macroEnabled.main+xml`，而文件是 .xlsx。
   根因：保存沿用基准包的内容类型，没按输出扩展名归一。
   修：fixups::normalise_workbook_ct(path, wants_macro) 在保存末段把 workbook 主类型
   改成与扩展名一致；带 VBA 却写 .xlsx 时直接报错（不静默丢宏）。
   细节：save_atomic 的临时名是 `.~x.xlsx.saving-<pid>`，扩展名要从临时名还原，
   否则 .xlsm 会被当成未知格式（这条是既有测试 save_failure_injection 逼出来的）。
   回归：qa01_formats.rs::xlsm_base_saved_as_xlsx_declares_non_macro_content_type。
   实测：features.xlsm → 我们另存 .xlsx → Excel 16 项读数与原始 .xlsx 完全一致。

三、.xls 输入
-------------
features.xls（Excel SaveAs 56）→ 我们 load → 另存 .xls → Excel 打开：
  a1.bold=True、b2.numfmt=#,##0.00、值全在（甲/10、乙/25、丙/7.5、丁/40）
  cf.count=0、dv 空、listobjects=0、names=0、freeze 0/0、hidden False、a1.fill=16777215
  → 结构性对象（条件格式/数据验证/表格/名称/冻结/隐藏）与填充、边框颜色都不保留。

原因与边界：.xls 走 calamine 读取，只给值；项目文档里一直是这个口径
（“calamine 只给值”，见 implementation-resume 归档）。所以 .xls 的兼容口径定为
「值 + 数字格式 + 粗体等基础样式」，不承诺 CF/DV/表格/名称/冻结/隐藏。
这条写进 not_done，不当成通过。

同时修掉一个真实崩溃：.xls 打开后另存 .xlsx 会 `读取基准工作簿目录失败`
（把二进制 .xls 当 zip 基准去读 xl/workbook.xml）。现在基准不是包时按全新文件重建。
回归：qa01_formats.rs::xls_input_loads_and_saves_as_xlsx。
日志：features-from-xls-excel.txt、xls-ours-excel.txt
