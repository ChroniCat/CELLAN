# C05 空值、布尔、文本比较的 Excel 语义

日期：2026-11-14 05:0x CST
审计基线：`formula/value.rs` 的 compare 曾把 Empty 当独立最低等级 → A1=0、A1=""、A1=FALSE 全 FALSE；
且比较运算与条件匹配（COUNTIF/SUMIF）共用同一套强制转换。

## 实机真值（Excel 16.0 / WPS 12.0，隐藏实例，只读打开夹具）

脚本：`scripts/excel_c05_probe.ps1`（同一夹具两份输出）；原始结果 `implementation-evidence/c05/probe-c05.json`，
逐条矩阵 `crates/core/tests/fixtures/c05/matrix.tsv`（47 条，Excel 与 WPS 逐行一致，diff=0）。

要点：

- 比较上下文：空引用按**对方类型**强制 —— `=A1=0`、`=A1=""`、`=A1=FALSE` 都是 TRUE，
  `<`/`>` 为 FALSE，`<=`/`>=` 为 TRUE；`=A1<"文本"` TRUE、`=A1=TRUE` FALSE。
- 类别排序：数字 < 文本 < 布尔；任何一侧是错误值就返回该错误。
- 条件匹配上下文与比较**不同**（本次新查出的差异）：
  - `COUNTIF(只有空单元格,0)=0`，`(">0")=0`，`(">=0")=0` —— 数字条件跳过空白；
  - `COUNTIF(...,"<>0")` 把空白算进来（空白单元格计数 = 1）；
  - `COUNTIF(...,"")` 只数空白，`("<>")` 数非空；
  - `COUNTIF(range,">0")` 只数真正的数字（文本 "5"、TRUE 不算），
    而 `COUNTIF(range,5)` 同时数数字 5 和文本 "5"；
  - `SUMIF` 与 COUNTIF 同一套条件规则（`SUMIF(A1:A6,0)=0`）。
- 聚合：`COUNTBLANK(A1:A5)=1`、`IF(A1,...)=假`、`IF(A1=0,...)` 走真空分支。

## 修改

- `Crit::matches` 接收条件前先处理空白：数字条件只在 `<>` 时命中空白；关系条件只比较 Number，
  等值条件才把文本数字一起比；布尔/错误在数字条件下按“不等”计。
- 比较 `compare` 保持“空值按对方类型强制”，与条件匹配彻底分开。
