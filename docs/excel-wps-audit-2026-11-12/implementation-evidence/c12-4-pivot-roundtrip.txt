C12.4 保真：Excel 存回 → 我们打开再保存 → 透视表还在
=====================================================
日期：2026-11-16
脚本：`scripts/c12_excel_resave2.ps1`（Excel 打开并另存）、`crates/core/examples/pivot_roundtrip.rs`（我们读入再保存）
探针：`scripts/c12_pivot_probe2.ps1`

一、链路
--------
```
multi-A.xlsx          ← 我们生成的 2 行字段透视（Excel/WPS 已验证）
   │ Excel 打开 + SaveAs
   ▼
rt-excel.xlsx         ← Excel 自己重新序列化过的包（12,054 字节）
   │ 我们的 xlsx::load + xlsx::save
   ▼
rt-ours.xlsx          ← 我们的保存链路写出的包
   │ Excel / WPS 打开
   ▼
PivotTables=1 rows=[地区,产品] data=[求和项:金额] range=A9:C16 src=Data!R1C1:R7C4
```

二、实测输出
------------
```
$ cargo run -p sheetcore --example pivot_roundtrip -- rt-excel.xlsx rt-ours.xlsx
loaded sheets=1 pivots_pending=0 path=Some("work/probe/c12/rt-excel.xlsx")
saved work/probe/c12/rt-ours.xlsx

$ scripts/c12_pivot_probe2.ps1 rt-ours.xlsx Excel.Application
sheets=1
Data: PivotTables=1
  name=数据透视表1 rows=[地区,产品] cols=[] data=[求和项:金额]
  range=A9:C16 src=Data!R1C1:R7C4

$ scripts/c12_pivot_probe2.ps1 rt-ours.xlsx KET.Application   # WPS 12.0
Data: PivotTables=1
  name=数据透视表1 rows=[地区,产品] cols=[] data=[求和项:金额]
  range=A9:C16
```

三、这条链路证明了什么
----------------------
1. 导入的透视表在**我们自己保存**之后不会丢（`pivots::restore_imported_parts` + 包结构修补这条路是通的）；
2. Excel 重新序列化后的包（字段名/属性写法跟我们的不完全一样）我们也能读、能原样写回；
3. 写回后的文件 Excel 和 WPS 都还能当可编辑透视表打开，不是退化成值。

四、注意
--------
- 探针里对 `RefreshTable()` 的调用在部分构建上会抛 COM 异常（"Call was rejected by callee" 一类），
  所以保真链路改成「打开 → 另存」；刷新语义已在 `c12_pivot_probe2.ps1` 的 values 段落里验证过。
- `pivots_pending=0`：导入的透视表不走待挂队列，靠 `restore_imported_parts` 保住，这一点与旧单字段路径相同。

五、仍未覆盖
------------
- 在 Excel 里改动透视表字段/布局后再存回（本用例只做了原样存回）；
- 删除源区域行/列后 Excel 刷新出的新布局与我们的 `pivot_shifts` 重映射的交叉验证。
