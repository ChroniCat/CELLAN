C14 部分加载失败不得伪装完整工作簿 — 实现与验收证据
=====================================================

一、缺陷与根因
--------------
`crates/core/src/xlsx.rs::load` 里每个部件的读取都是 `if let Ok(...)`：

    if let Ok(range) = reader.worksheet_range(name) { ... }      // 失败 → 空表
    if let Ok(st)    = reader.worksheet_style(name) { ... }      // 失败 → 无格式
    if let Ok(forms) = reader.worksheet_formula(name) { ... }    // 失败 → 无公式
    Ok(v) => all.extend(v), Err(_) => eprintln!("线程异常退出")   // 整组表消失

结果：损坏的工作表被当成"空表"成功打开，应用显示"打开成功"，
用户一按 Ctrl+S 就把**没读到的东西**永久覆盖掉。原文件哈希在打开阶段不变，
但覆盖保存后无法恢复。

二、修改
--------
1. 新增结构化诊断（`crates/core/src/xlsx.rs`）：

       pub struct LoadProblem { sheet: Option<String>, part: String, what: String, detail: String, fatal: bool }
       pub struct LoadDiag { problems: Vec<LoadProblem> }
       impl LoadDiag { is_complete(), has_fatal(), summary() }

   - 单元格数据 / 公式 / 样式读取失败 → `fatal = true`（覆盖保存会丢用户数据）；
   - 稀疏大表退回通用解析器 → `fatal = false`（能读，只是慢）；
   - 解析线程 panic → 记一条部件级致命问题；
   - workbook.xml 声明了但没有解析结果的工作表 → 致命问题（防"少一张表还报成功"）；
   - 图表部件整份读取失败 → 致命问题。

2. `pub fn load_diag(path) -> Result<(Workbook, LoadDiag)>`；`load()` 变成
   `load_diag(..).map(|(wb, _)| wb)`，老调用点行为不变。
   返回前 `wb.load_incomplete = diag.has_fatal()`。

3. `Workbook.load_incomplete`（`model.rs`）：打开不完整的簿子**不能拿原文件当保存基准**
   （坏 XML 会让 umya 解析 panic，且写回等于丢数据）。`save_plain_base` 的基准选择改为
   `filter(|p| p.exists() && !wb.load_incomplete)`。

4. 应用层（`crates/app/src/main.rs`）：
   - `OpenMsg::Loaded` 带上 `LoadDiag`；`SheetApp.load_diag` 保存诊断；
   - `save(force_dialog=false)` 在 `load_diag.has_fatal()` 时**拒绝就地保存**，
     状态栏写明原因并提示「另存为」保存抢救副本，不启动写盘任务；
   - 「另存为」仍然允许；另存成功后清空诊断并把 `wb.load_incomplete` 复位。

三、测试
--------
`crates/core/tests/load_diag.rs`（6 passed / 0 failed）：

| 用例 | 合成损坏 | 断言 |
|---|---|---|
| `healthy_workbook_reports_nothing` | 无 | `is_complete()`，A1/B2 值正确 |
| `broken_sheet_xml_is_fatal_not_silently_empty` | 把 sheet XML 截断成 `<worksheet><sheetData><row>` | 点名「数据」表、`fatal`、what 含"单元格/数据"；`load()` 仍返回但表是空的；原文件字节数不变 |
| `missing_sheet_part_is_reported` | 删除整份 worksheet 部件 | 打开失败 **或** diag 有致命项；不得"完整" |
| `broken_styles_are_reported_as_fatal` | styles.xml 写坏 | 打开失败时错误必须可定位；若打开成功则必须有致命"样式"问题 |
| `missing_shared_strings_is_reported` | 删除 sharedStrings.xml | 若解析器仍能打开，diag 必须非空 |
| `load_wrapper_still_returns_workbook_for_healthy_files` | 无 | `load()` 兼容入口行为不变 |

应用层：`crates/app/src/edit_regression_tests.rs::incomplete_load_blocks_overwrite_but_allows_rescue_save_as`
（`cargo test -p app --bin app incomplete_load_blocks` → 1 passed）：

1. 造正常簿 → 用 `fixups::write_parts` 把工作表 XML 换成坏片段；
2. `load_diag` 确认 `has_fatal()`；
3. `app.save(false)`：状态栏含「禁止覆盖保存」、`tasks.saving` 仍为 None、原文件 SHA256 不变；
4. `app.save(true)`（`SC_SAVE_AS`）：另存成功，抢救副本可被 `xlsx::load` 读回，
   `app.load_diag` 清空（后续保存不再被挡住）。

四、变异验证
------------
| 变异 | 结果 |
|---|---|
| M1 单元格读取失败改 `fatal:false` | 2 failed（坏表用例 + 缺表用例） |
| M2 删掉"声明了但没解析结果"的检查 | 0 failed ——**未被抓住**；现有夹具里删部件会让解析器直接打不开，走不到该分支。该检查是 panic 线程的兜底，暂无合成手段覆盖，已如实登记 |
| M3 基准选择去掉 `!wb.load_incomplete` | app 用例失败：umya 解析坏 XML panic，抢救副本写不出来 |
