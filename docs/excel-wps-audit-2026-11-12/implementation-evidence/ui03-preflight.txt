# UI-03 写入入口统一门禁（保护 + 协作锁 + 全有或全无）

日期：2026-11-14 00:4x CST
审计基线指出的旁路：Delete 只查活动格协作锁、没有保护判断；`replace_current`/`replace_all`/
`run_dedup`/`run_sort`/验证下拉直接改模型；保护对话框宣称“锁定单元格不能编辑”，实际是整表保护。

## 现状

统一门禁 `write_preflight_on(sheet, keys, 动作)`（main.rs:3972）：

1. `deps_pending`（大文件后台依赖未就绪）→ 拒绝；
2. 该表 `protection.is_some()` → 拒绝，提示"工作表「x」受保护：不能<动作>"；
3. 遍历**所有目标格**，任何一格在 `locks` 里有别人持有 → 整批拒绝，提示持有人 + 单元格。

先收集完整读写范围、再判断，所以不存在"写了一半才发现被锁"。

已接入门禁的入口（grep `write_preflight`）：

| 入口 | 覆盖范围 |
| --- | --- |
| 粘贴 / 剪切 | 目标块；剪切还要过源表门禁（`write_preflight_on`） |
| 选择性粘贴 | 锚点 + 剪贴板矩阵尺寸 |
| 拖动移动 `move_selection_by` | 源块 ∪ 目标块 |
| 填充 `fill_to`、计算列填充 | 目标块 |
| 插入并移动 `shift_insert_by` | 源块 + 被移动的行/列 + 租约表里的稀疏格 |
| 排序 / 去重 / 分列 | 整个数据区 |
| 清除内容/格式/全部 `clear_rects` | 所有非连续选区去重后的全部格 |
| 替换 / 全部替换 | 被替换的格（跨表时按表判断） |
| 验证下拉 `dv_pick_apply` | 目标格 |
| 格式、格式刷、合并 | 目标块 |

## 回归

-> 13 passed / 0 failed

新增两条矩阵测试：

- `every_write_entry_is_blocked_by_one_remote_lock`：B2 被远端锁住，选区 A1:B2 上依次执行
  拖拽移动、合并、分列、去重、向下填充、选择性粘贴（2×2）、插入并移动 —— 数据、样式、
  undo 深度、dirty 全不变，状态栏指出锁持有人“丁”。
- `paste_cut_replace_and_dv_pick_respect_a_remote_lock`：B1/B2 同时被锁，
  普通粘贴、剪切粘贴（源被锁）、替换、全部替换、验证下拉全部拒绝，同样不动模型。

既有覆盖：`protected_sheet_blocks_delete_replace_dedup_fill_and_dv_pick`、
`protected_sheet_blocks_clear_buttons_multi_select_format_and_quick_sort`、
`one_locked_cell_blocks_multi_select_clear_format_and_sort`、
`one_locked_cell_blocks_the_whole_clear`、
`protected_sheet_blocks_clearing_and_formatting`、`cut_from_a_protected_sheet_cannot_be_pasted`、
`fill_shortcuts_are_blocked_by_protection_tail_locks_and_pending_deps`。

## 真实窗口

受保护工作簿 `ui03.xlsx`（A1=7、B1=`=A1*2`，sheet.protection=1），选中 A1 按 Delete：

- `SC_DUMP`：A1 仍为 "7"，B1 仍为 "14"；
- `ui03-protected-delete.png` 状态栏：`工作表「保护」受保护: 不能清除内容 (先"审阅 → 撤销保护")`。

## 边界

- 细粒度 locked/hidden 单元格权限属于 C15，本切片按现状做整表保护 + 协作锁的入口一致性，
  没有把 C15 的能力写进这里。
- 按键仍是事件注入真实帧循环（本机 RDP 断开，无法投递系统级按键）。
