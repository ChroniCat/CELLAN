C08 无损更新自定义文档属性 — 实现与验收证据
============================================

一、缺陷与根因
--------------
`crates/core/src/external.rs::write_sources` 原先每次**新造整份** `docProps/custom.xml`，
只写本应用的 `_sc_src_*` 数据源属性：

    let mut xml = String::from("<?xml ...><Properties ...>");
    for (i, s) in sources.iter().enumerate() { ... push 一个 property ... }
    // 结束标签，然后 append_entry 覆盖整个部件

后果：用户/第三方写入的 `Customer`、`Revision`、`Reviewed`、`Approved` 等属性在
「改数据源 → 保存」后全部消失；删除最后一个数据源时也不会清理，残留旧属性。
调用点 `xlsx.rs` 还有 `if !wb.sources.is_empty()` 前置条件，空数据源时整个函数不执行。

二、修改
--------
1. `write_sources_from(path, sources, base: Option<&Path>)`
   - 先读已有 `docProps/custom.xml`；**优先从 base（保存前原文件）读**，因为 umya 重写包后
     新包里可能已经没有该部件。
   - `parse_third_party_props`：逐段扫描 `<property ...>`（含自闭合），
     保留原始 XML 片段与 pid，只按名称前缀 `_sc_src_` 判定归属。
   - 第三方属性的**类型元素、命名空间前缀、fmtid、pid、值原文一律不动**（直接拼接原片段）。
   - 应用属性重写为 `_sc_src_N`，pid 从 `max(保留 pid)+1` 连续分配，稳定不重复。
   - 名称与值分别走 `xml_escape_attr` / `xml_escape_text`（`& < > "`）。
   - 若「无第三方属性 且 无数据源」→ `remove_custom_part`：删部件、删 `_rels/.rels` 里
     指向它的 Relationship、删 `[Content_Types].xml` 里的 Override。
   - 部件缺失时补 Relationship（rId 取现有最大值+1）与 Content-Type Override。
2. `write_sources(path, sources)` 保留为兼容包装（等价于 `base=None`）。
3. `xlsx.rs` 调用点去掉 `!wb.sources.is_empty()` 条件，改为总是调用并传入 `restore_base`：
   删掉最后一个数据源时也必须清理本应用属性；第三方属性保持原样。
   仍受 `SC_NO_SRC_PROP` 开关控制（既有测试约定）。

三、测试（crates/core/tests/custom_props.rs，8 passed / 0 failed / 2 ignored）
---------------------------------------------------------------------------
夹具 `book_with_props()`：正常保存一个簿子后，手工装上四类第三方属性
（`vt:lpwstr` / `vt:i4` / `vt:filetime` / `vt:bool`，pid 2..5）与正确的 rels / Content_Types，
模拟「Excel 存出来的带属性文件」。

1. `third_party_properties_survive_writing_sources`
   写入 `_sc_src_1` 后四类属性的 pid/类型/值逐项仍在；应用属性拿到 pid=6（不撞车）。
2. `repeated_saves_do_not_duplicate_or_drift`
   同参数连续保存两次 → custom.xml 完全一致；改名换源后旧 `_sc_src_1` 值消失、
   `_sc_src_2` 被删、第三方属性不变、`_sc_src_1` 只出现一次。
3. `deleting_the_last_source_removes_only_app_metadata`
   删最后一个数据源：第三方属性在、`_sc_src_` 全无；
   没有第三方属性时部件本身、Relationship、Content-Type Override 一并删除。
4. `names_and_values_with_markup_are_escaped`
   值含 `& < > "`、名称含 `& "` → 输出 `&amp; &lt; &gt; &quot;`，
   并用 quick-xml 全量解析确认是合法 XML。
5. `save_path_keeps_third_party_props_end_to_end`
   走真实 `xlsx::save`：加载 → 设 sources → 保存 → 属性在；
   再加载 → 清空 sources → 保存 → 第三方仍在、应用属性清零；
   另存到新路径 → 第三方属性跟着走。
6. `base_argument_reads_props_from_the_original_file`
   目标包内没有 custom.xml（模拟 umya 重写后的状态），从 base 读回四类属性并合并。
7. `refreshing_a_csv_source_keeps_third_party_props`
   真实 `import_csv` 刷新目标区后保存：第三方属性不变，`_sc_src_1` 不重复。
8. `sources_with_arbitrary_labels_land_in_the_app_namespace`
   回归（round17 抓到）：`Source.name` 是「导入1」这类任意文字时，旧写端原样写进属性名，
   读端只认 `_sc_src_` 前缀 → 源保存后消失。写端现在把名字归一到 `_sc_src_N` 并保证唯一；
   测试用「导入1」+「_sc_src_1」两条源，断言属性表里没有「导入1」、名字唯一、两个源都能读回。
   （round17 的 `save_failure_injection::injected_failures_in_conditional_steps_abort_the_save`
   正是因为测试里用了 name=「导入1」触发 debug_assert 而失败，修完复跑 11 passed。）

ignored（需外部软件或人工驱动）：

十一、03:05 复核整改：真正的 XML 命名空间解析
--------------------------------------------
复核指出的三个风险（前缀 `<cp:property>` 漏读、前缀未绑定、单引号属性误判）均已修：

1. 写端 `parse_custom_props` 改用 `quick-xml::NsReader::read_resolved_event_into`，
   按 **命名空间 + local name** 判定属性元素，不再字符串找 `<property`；
   - 属性值统一走 `quick_xml::escape::unescape`，单引号 `pid='2'`、`name='客户'` 都能正确取值；
   - 保留项以原始 XML 片段搬运，根标签原文（含全部 `xmlns:*` 声明）原样保留；
   - 新属性沿用文件里的前缀（`cp:` 或空），不会写出未绑定前缀；
   - VT 前缀从根上的声明里取（`v:`、`vt:` 都行），缺声明时才补 `xmlns:vt`。
2. pid：保留项按最大值继续；本应用已有的 `_sc_src_N` **按名字复用原 pid**，连续保存不漂移。
3. 读端 `read_all_props` 同样按命名空间解析，`<cp:property>` 也能读回数据源。

新增夹具 `prefixed_properties_single_quotes_and_alt_type_prefix_survive`：
第三方属性写成 `<cp:property ... pid='2' name='客户'><v:lpwstr>甲公司</v:lpwstr>`，断言

- `pid='2' name='客户'` 原文保留、`<v:lpwstr>甲公司</v:lpwstr>` 与 `<v:i4>42</v:i4>` 保留、fmtid 保留；
- 根上 `xmlns:cp` 与 `xmlns:v` 都还在（没有未绑定前缀）；
- 新属性写成 `<cp:property`（不混用默认命名空间）；
- 全部 pid 唯一（含新分配的）；
- `read_sources` 能读回 1 条源。

测试结果（当前源码）：

- `cargo test -p sheetcore --test custom_props` → **9 passed / 0 failed / 2 ignored**
  （原 8 项 + 前缀/单引号/替代前缀 1 项）。
- 早前 `repeated_saves_do_not_duplicate_or_drift` 因 pid 漂移曾失败（8/9 vs 6/7），
  改为按名字复用后恢复通过——这条就是"连续保存不重复、不漂移"的直接证据。

十二、03:26 复核整改：单引号命名空间声明
--------------------------------------
风险：判断“根上有没有 `xmlns:vt`”用的是 `root_raw.contains("xmlns:vt=\"URI\"")`，
合法文件写成 `xmlns:v='URI'`（单引号）会被误判成“没声明”，再追加一条同名声明，
同一元素上出现两个 `xmlns:v` → XML 非法。

修法：改用**解析出的声明集合**判断（`parse_custom_props` 已记录 VT 前缀，
`vt_prefix.is_some()` 即已声明），不再做字符串匹配。

新增夹具 `single_quoted_namespace_declarations_are_not_duplicated`：
根写成 `xmlns=...` / `xmlns:v='...'`（单引号），属性 `<v:lpwstr>`；断言

- `docPropsVTypes` 在整份 XML 里只出现 **1 次**（无重复声明）；
- 单引号声明原文保留；
- 新属性沿用 `v:` 前缀，不写 `<vt:lpwstr>`；
- `read_sources` 仍能读回 1 条源。

结果：`cargo test -p sheetcore --test custom_props` → **10 passed / 0 failed / 2 ignored**。
变异 M4（把判断改回 `root_raw.contains(...)`）→ 该用例失败，已还原。

仍未执行：Excel「属性」对话框自定义页列表的屏幕截图（该截图不是 C08 原文验收项，
09:26 独立复核明确不要求补空白属性页截图，也不作为门禁）；属性对象可见性已由第十
三节的 cscript 实测替代，不再用 PowerShell 的 `CustomDocumentProperties=0` 推断不可见。

十三、08:57 实机补证：cscript late binding 读取属性对象
------------------------------------------------------
本机 PowerShell 5.1 动态 COM 绑定对 `Workbook.CustomDocumentProperties` 会抛
`System.NullReferenceException`；这是绑定层问题。同一台机器用 cscript late binding
读取 `Workbook.CustomDocumentProperties` 正常。

1. 直接用 app 的真实异步保存路径（不是模型注入）：
   `target/debug/app.exe work/c08_verify/input.xlsx`，
   `SC_SAVE_ASYNC=work/c08_verify/app_saved.xlsx`。
   日志 `[save] 已保存 .../app_saved.xlsx`；另存后 `docProps/custom.xml` 仍含
   Customer/Revision/Reviewed/Approved/_sc_src_1 五项。
2. Excel 16.0 读取 `app_saved.xlsx`：`excel count=5`，
   Customer=original-metadata(type4)、Revision=42(type1)、
   Reviewed=2024-03-01 08:30(type3)、Approved=True(type2)、
   `_sc_src_1=CSV|C:/data/ledger.csv|,|1|0|0|2|2|auto||q34`(type4)。
3. Excel 打开 `app_saved.xlsx` → B2=99 → SaveAs `app_excel_rt.xlsx` → 重新读取：
   仍 `excel count=5`，五项名称/类型/值不变。
4. WPS 12.0 读取同一个 `app_saved.xlsx`：`wps count=5`，五项名称/类型/值不变。
5. WPS 打开 → B2=99 → SaveAs `app_wps_rt.xlsx` → 重新读取：
   `wps count=8`，前五项原样，另加 WPS 自有的 ICV/KSOProductBuildVer/CalculationRule
   （这正是第三方属性应被保留、WPS 自己追加属性的正常行为）。
6. `cargo test -p sheetcore --offline --test custom_props` 当前源码：
   **10 passed / 0 failed / 2 ignored**。

缓存注意：同一个文件路径在 Excel 已被打开过后，直接再次读取该路径可能拿到旧的
属性缓存（本次 `c08.xlsx` 直读为 3 项，复制成新文件名或读取 app 新保存的文件为 5 项）；
因此验收证据使用新保存的 `app_saved.xlsx` 与 Office 另存产物，不把旧路径缓存结果
当作属性内容。属性对话框自定义页列表仍只有空白截图，不能声称已目视核对列表；
但 Excel/WPS 自身属性对象的读取结果已逐项实测。
