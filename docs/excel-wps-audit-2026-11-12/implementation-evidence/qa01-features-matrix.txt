四、这一轮抓到的三个真实缺陷（都已修 + 有回归）
------------------------------------------------
1) styles.xml 里 <dxfs> 被写在 <extLst> 之后
   现象：只要保存带条件格式的新文件，Excel 打不开（COMException: 不能取得类 Workbooks 的
   Open 属性；包本身不报错，是被判损坏）。
   根因：patch::replace_dxfs 的「已有 dxfs 就原地替换」分支保留了 umya 把 dxfs 排在
   <extLst> 后面的位置；另外「没有 dxfs」分支插在 </styleSheet> 前，同样落到了 extLst 后面。
   CT_Stylesheet 的顺序要求 dxfs 在 tableStyles / extLst 之前。
   修：先摘掉旧段，再统一插到 <tableStyles / <extLst 之前。
   回归：patch.rs::dxfs_already_at_tail_is_moved_before_table_styles、
         patch.rs::empty_dxfs_placeholder_is_replaced_not_duplicated。

2) 表格 displayName 用了单元格引用（T1）
   现象：带表格对象的新文件 Excel 打不开；把 displayName 改成 T1_ 立刻能开（对照实验
   u-display.xlsx OK / only-table.xlsx FAIL）。
   根因：Excel 拒绝把形如 A1、T1 的字符串当表格 displayName。我们直接照抄了 name。
   修：写部件时判定 A1 / R1C1 形态，命中则追加下划线（与 Excel 自己另存的行为一致）。
   回归：table.rs::table_display_name_looking_like_a_cell_reference_gets_underscore、
         table.rs::table_display_name_that_is_not_a_cell_reference_is_kept。

3) 新工作簿冻结窗格保存即丢
   现象：冻结 B2 后保存，Excel/WPS 重开都没有分割线（pane 元素根本不在 XML 里）。
   根因：set_freeze_xml 只在已有 <sheetView> 上挂 <pane>；新建工作簿的 sheet XML 没有
   <sheetViews>，于是直接 return。
   修：没有 <sheetViews> 时按 schema 顺序补 <sheetViews><sheetView workbookViewId="0">
   <pane .../></sheetView></sheetViews>（插在 <sheetFormatPr / <cols / <sheetData 之前）。
   回归：patch.rs::freeze_on_sheet_without_sheet_views_creates_them。

五、探针本身的一个坑（记录，避免误判）
--------------------------------------
最初 WPS 读到 freeze.splitcol=0。原因不是文件：探针里写了
`$app.ActiveWindow.SplitRow = $app.ActiveWindow.SplitRow`（本意是激活窗口），
WPS 在赋值时把列分割清掉，于是读到假的 0。去掉这行后 WPS 读到 1/1。
对照：WPS 自己冻结另存的文件 wps-freeze.xlsx（state="frozenSplit"）读 1/1；
Excel 另存的 gold-freeze.xlsx（state="frozen"）WPS 也读 1/1。
