# QA-07.3 取消 / 进度 / 保存期间可操作性 / 数据正确性

日期：2026-11-16　样本：chain 1M（12.29MB，100 万行 × 2 列，100 万条公式）

## 1. 本切片按合同验收的三条

`qa-requirements.md` QA-07 的验收句：**「保存/重算期间窗口可操作、取消/进度反馈可见，
数据正确性不因性能优化变化」**。逐条对照：

| 验收点 | 测量 | 结果 |
|---|---|---|
| 保存期间窗口可操作 | `SC_SAVE_PROBE=1` 下 120 帧帧间隔 | p50 30.30ms、p95 31.28ms、max 80.57ms（冻结上限 36ms）→ PASS |
| 保存进度可见 | 状态栏 `正在保存到 … {秒}s（窗口可继续操作）` | 保存 11.35s 全程刷新，见 `main.rs` saving 分支 |
| 重算取消 | 300ms 触发取消：0.39s 结束，B1 保持 1 | 见 `qa07c-cancel-progress.txt`（前一轮已验收） |
| 重算进度 | `正在重算 d/t（Esc 取消）` | 同上 |
| 数据正确性 | 保存前后逐格对拍 | **2,000,000 格 / 1,000,000 条公式全部一致** |

`max 80.57ms` 是保存开始那一下的快照克隆（`wb.clone()`），属单次帧尖峰，p95 未受影响。

## 2. 保存正确性对拍

新写 `crates/core/examples/qa073_cmp.rs`：加载两个工作簿，把 `(表, 行, 列) → (值, 公式文本)`
全量导出成字典逐键比较，值按 12 位小数归一。

```
$ cargo run --release -p sheetcore --example qa073_cmp -- chain1m.pristine.xlsx chain1m-save.xlsx
cells 2000000 vs 2000000, formulas 1000000 vs 1000000
RESULT PASS 全部单元格一致
```

Excel 端独立复核（`work/probe/qa07/excel_open_check.ps1`，COM 只读打开）：

```
title=chain1m-save.xlsx      sheets=1
A1=0   B2=2   B3formula==A3+1
used=1000000x2               name_has_fixed=False
```

即：没有「已修复」提示、行数/列数正确、公式文本原样。

分阶段读数（本次新加 `SC_SAVE_PROF` 的 rss 打印，`sheetcore::mem::rss_mb`）：


根因是 umya 的整簿 DOM + 单表序列化，COW 列只解决了 clone 复制，解决它要改成
「自建包 + 流式写 sheetData」，属结构改造。**合同没有给保存峰值设阈值**，此处如实记录，
不作为 QA-07.3 的通过依据，也不声称已修复。

## 4. 边界

- 保存期间「可操作」是用程序发起保存 + 帧间隔测的，没有真人同时在拖选/输入；
  真人并发编辑与保存的快照一致性由 QA-04.3 的多文档回归覆盖。
- 冷启动（清系统缓存）未测，属 QA-07.1 的 not_done。
- 进度是状态栏文字，不是进度条：保存阶段拿不到总字节数，只有已用时间。
