UI-30.1 点击矩阵：283 个功能区动作逐个真跑，269 个走完，14 个按下述理由跳过
================================================================================
日期：2026-11-16

一、做法
--------
测试 `edit_regression_tests::click_matrix_every_ribbon_action_is_handled`：
1. 用 `ribbon::tests::xml_actions()` 从 `customUI.xml` 收集全部控件动作
   （按钮/开关/拆分的菜单项/下拉项），排序去重 —— 共 **283** 个。
2. 每个动作新建一个干净 `SheetApp`，真调 `ribbon_action(action, ctx)`。
3. 只要落到兜底分支，`unhandled_action` 就会被写值 → 测试失败并列出全部漏网动作。
4. 跳过名单 `CLICK_MATRIX_SKIP` 里每一条都必须真实存在于 XML（拼错/过期即失败），
   防止名单变成"把失败藏起来"的工具。

二、结果
--------
执行 269 个动作，0 个落兜底；跳过 14 个，原因如下：

  FileOpen / FileSaveAs / FileSave   —— rfd 原生对话框，测试里无人点会阻塞
  ExportPdf                          —— rfd 选 PDF 路径
  CompareBooks                       —— rfd 选比较文件（dispatch 已另有测试）
  MacroExport                        —— rfd 选导出路径（无宏时走状态提示，已有测试）
  InsertPicture                      —— rfd 选图片
  ImportWorkbook / ImportCsv         —— rfd 选导入文件
  ImportWorkbook / ImportCsv         —— 同上
  Hyperlink                          —— 链接输入/文件选择
  OpenInNewTab                       —— rfd 打开文件
  Share / AutoShare                  —— 真起局域网监听（网络副作用）
  CheckUpdate                        —— 联网检查更新（等网络超时，实测卡住）

三、过程中发现并处理的三件事
----------------------------
1. 第一版矩阵跑到 `CheckUpdate` 卡死（联网等超时）→ 加入跳过名单并注明。
2. `ImportWorkbook` / `Hyperlink` / `OpenInNewTab` 同样因对话框阻塞被逐个发现。
3. 初版跳过名单里写了 3 个 XML 里并不存在的动作（InsertHyperlink/OpenFile/LoadCompare，
   是凭印象写的）→ 由「名单必须存在于动作集合」断言当场抓出并删除。

四、验证
--------
- `cargo test -p app --bin app`：**337 passed**（work/goal-logs/ui30c-app.log）
- `cargo test -p sheetcore`：**106** 个测试二进制 0 failed（work/goal-logs/ui30c-core.log）
- 单元测试产出：`SC_MATRIX_LOG=1` 时打印每个动作，实测 269 行。

五、仍然不算通过的部分
----------------------
- 被跳过的 14 个动作**没有**做点击验证，只做了「有 dispatch 臂」的静态校验和个别专项测试；
  它们要等有人值守的 GUI 会话里点（原生对话框必须真人选路径）。
- 点击矩阵验证的是「有实现、不落兜底」，**不**验证每个动作的业务效果是否正确；
  业务效果仍由各功能自己的回归测试保证。
