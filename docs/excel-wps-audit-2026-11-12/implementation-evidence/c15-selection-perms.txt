# C15 选择单元格权限：从「只序列化」到真实选择入口

日期：2026-11-14
触发：监督复核指出 `select_locked` / `select_unlocked` 之前只落在配置与 XML 属性上，
真实选择入口（鼠标、键盘、名称框）没有执行，等于「能配但不生效」。

## OOXML 语义（沿用本任务已实测的规则）

`sheetProtection` 的布尔属性是「存在且为 0 = 允许，缺省 = 禁止」；
选择两项是例外，Excel 默认允许，所以「禁止选择」写成 1：

```xml
<sheetProtection sheet="1" selectLockedCells="1"/>    <!-- 禁止选锁定格 -->
<sheetProtection sheet="1" selectUnlockedCells="1"/>  <!-- 禁止选未锁格 -->
```

解析端 `ProtPerms` 仍按「true = 允许」存，`to_attrs` 反向写出。

## 实现（`crates/app/src/main.rs`）

新增两个方法：

```rust
fn sel_blocked_at(&self, r, c) -> bool   // 受保护表：锁定格看 select_locked，未锁格看 select_unlocked
fn block_selection(&mut self)            // 状态栏：工作表受保护：不允许选择该区域的单元格
```

在四个真实选择入口执行：

1. **鼠标按下**（`pointer.primary_pressed`）：命中格 / 合并区锚点被判 forbidden 时不改选区，
   状态栏说明原因；
2. **拖拽扩选**：拖到 forbidden 格时不更新 `sel_end`；
3. **方向键 / Shift+方向**：目标格 forbidden 时不移动活动格；
4. **名称框定位**（`goto_name`，含名称指向的区域）：目标 forbidden 时不跳转。

受保护判定还要求 `protection.sheet == true`，避免 `sheet="0"` 的文件被误当受保护。

## 2026-11-14 监督补漏：Enter/Tab 与整块名称框

监督指出两处原范围绕过，已修并加回归：

1. `advance_active`（Enter / Shift+Enter / Tab / Shift+Tab）原来只按可见行列推进，
   不查选择权限。现在：
   - 有导航矩形时，逐个候选格查 `sel_blocked_at`，被禁选的格跳过继续找；
   - 无导航矩形时，沿方向反复 `next_visible_row/col` 跳过被禁选格，回到起点或
     2 万次上限则停在原地并在状态栏说明；
   - 锁定格与未锁格分别按 `select_locked` / `select_unlocked` 判定。

2. 名称框 `A1:B2` 原来只查左上角 A1。现在 `rect_sel_blocked(a,b)` 逐格检查
   整个矩形（超过 20 万格时保守地按权限位判断），任何一格禁选就整块拒绝，
   与鼠标拖选的门禁一致。

回归（app `--bin app`）：

```text
edit_regression_tests::keyboard_advance_skips_cells_without_selection_permission ... ok
edit_regression_tests::name_box_range_rejects_when_any_cell_is_forbidden ... ok
```

第一条覆盖：B1/C1 未锁时 Tab 停在 C1；再 Tab 不进入锁定的 D1；全锁时原地不动并提示。
第二条覆盖：`A1:B2` 含锁定格被拒、只选 `B1` 可以定位。
