C04 1900 与 1904 日期体系
=========================
日期：2026-11-13 UTC+08   对标：core-requirements.md C04
本机 Excel 16.0 与 WPS 的 1904 开关行为一致：同一张工作簿里「插入的日期」序列差 1462，
显示仍是同一天；1904 簿另存后 flag 不丢。

一、原缺陷（修复前的事实）
--------------------------
`grep -rn "1904\|1462" crates/core/src` 命中 0（只有 dist.rs 里一个浮点常量巧合）。
即：完全不认 `workbookPr/@date1904`，所有日期按 1900 算。打开 Excel 的 1904 工作簿时，
序列 1 会显示成 1900-01-01（应为 1904-01-02），整本日期整体偏移 1462 天；
另存也不会写这个 flag，等于把用户的工作簿悄悄改成 1900。
`.xls` 侧的 `DATEMODE (0x0022)` 同样没读没写。

二、改动
--------
1. `model.rs`
   - `pub enum DateSystem { D1900, D1904 }`（`is_1904()`、`OFFSET = 1462`）；
   - `Workbook.date_system`，默认 `D1900`；`Workbook::date_to_serial / serial_to_date`
     两个便捷方法，避免各处各写一套偏移。
2. `formula/functions.rs`
   - `date_to_serial_in(sys, y, m, d)` / `serial_to_date_in(sys, serial)`：
     1904 基准 = `days - days_from_civil(1904,1,1)`，没有 1900 闰年 bug；
     1900 分支保留原 `+25569/+25568` 的伪闰日行为。
   - 线程本地 `DATE_SYSTEM` + `current/set/with_date_system`：
     函数库签名不变（`&[Arg]`），由求值入口设置。
   - `now_serial()`：`NOW/TODAY` 改成**本地时间**（`GetLocalTime`，含夏令时），
     1904 体系再减 1462。旧实现直接用 UTC，本机 UTC+08 每天 00:00–08:00 会显示前一天
     （本轮实测：本地 2026-11-13 01:0x，旧 `TODAY()` 显示 2026-11-12）。
3. `formula/mod.rs`
   - `Calc::new` 用 `wb.date_system` 设线程本地，`Drop` 恢复外层值 ——
     `eval_formula`/`eval_cell`/`recalc_all`/`recalc_dirty` 全走这一条路，不漏入口。
   - 重导出 `date_to_serial_in/serial_to_date_in/current_date_system/with_date_system`。
4. `xlsx.rs`
   - 读：`patch::read_date1904(path)` 解析 `xl/workbook.xml` 的 `workbookPr/@date1904`
     （`"1"` 与 `"true"` 都认），load 时写入 `Workbook.date_system`；
   - 写：`save_plain_base` 里与 umya 的 `book.date1904()` 对比后 `set_date1904(...)`，
     保证 1904 簿存回去还是 1904（新建文件也写）。
5. `xls_read.rs` / `xls_write.rs`
   - 新 `read_date1904(stream)`：扫 `DATEMODE(0x0022)`；
   - 写端 `set_datemode(&mut prefix, is_1904)`：**改骨架里已有的那条记录**而不是追加
     —— 内嵌骨架来自 Excel 生成的空簿，本来就有一条 `DATEMODE=0`，追加会让读端先撞上 0
     （这正是本轮第一版测试失败的原因，已改正）。
6. `style.rs`
   - `format_date_in(sys, serial, fmt)`；`format_value_in(sys, v, fmt)` 用
     `with_date_system` 包住整段渲染；星期几按体系分别算：
     1900 体系 `serial 25569 = 1970-01-01（周四）`，1904 体系 `serial 0 = 1904-01-01（周五）`。
   - 应用里 5 处 `format_value` 调用全部换成 `format_value_in(self.wb.date_system, ..)`。
7. `pivot.rs` 的三处调用（`compute` ×2、`row_values`）用 `with_date_system(...)` 包住，
   按年/月分组的标签不会在 1904 簿里错位。

三、验收用例 `crates/core/tests/date_system.rs`（8 项，全绿）
------------------------------------------------------------
| 用例 | 断言 |
|---|---|

| `xls_datetime_mode_survives_a_roundtrip` | 1904 簿存 `.xls` → `DATEMODE` 读回 1904、值不变；1900 簿存 `.xls` 读回仍是 1900 |

五、跨簿粘贴策略（明确规则，不是「所有数值加减 1462」）
------------------------------------------------------
- 同一工作簿内复制粘贴：序列就是本簿体系的序列，**不做任何数值调整**，格式跟着走。
- 系统剪贴板（到 Excel/WPS 或反过来）：承载的是**显示文本**，不是序列；
  本项目按文本落格，不会把文本偷偷当序列再偏移，因此不存在「粘贴时被加 1462」的路径。
- 富文本（XML Spreadsheet）粘贴的数值按字面数值落格，同样不偏移。
  跨工作簿要带格式的日期仍以文本/显示值为准，这是本项目的既定边界（未做 Excel 那种
  携带源簿 flag 的私有剪贴板格式）。
- `.xls` 与 `.xlsx` 互转：走同一 `Workbook.date_system`，写端按体系写 flag / DATEMODE，
  序列不动（禁止「转格式时补 1462」）。
