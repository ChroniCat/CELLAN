C04 1900 与 1904 日期体系（全路径共用基准）
============================================
日期：2026-11-13 UTC+08   依据：core-requirements.md C04
原文要求：日期函数、数字格式化、条件格式、数据验证、透视表日期分组、图表轴
**共用同一个基准**；另存后两款软件打开不漂移；日期减法；日期与普通数字的跨簿复制分别测试。

一、原缺陷（修复前的事实）
--------------------------
`grep -rn "1904\|1462" crates/core/src` 命中 0（只有 dist.rs 一个浮点常量巧合）。
即完全不认 `workbookPr/@date1904`：1904 工作簿里序列 1 显示成 1900-01-01（应 1904-01-02），
整本日期偏 1462 天，另存还会把 flag 丢掉。`.xls` 的 `DATEMODE (0x0022)` 同样没读没写。

二、改动
--------
1. `model.rs`：`DateSystem { D1900, D1904 }`（`is_1904()`、`OFFSET=1462`）、`Workbook.date_system`、
   `date_to_serial/serial_to_date`。
2. `formula/functions.rs`：`date_to_serial_in/serial_to_date_in`（1904 无 1900 伪闰日）；
   线程本地 `DATE_SYSTEM` + `with_date_system`；`NOW/TODAY` 改本地时间（`GetLocalTime`）。
3. `formula/mod.rs`：`Calc::new` 设线程本地、`Drop` 恢复；重导出；`date_to_serial_pub/
   serial_to_date_pub` 走线程本地（CF/DV/透视都从这里拿基准）。
4. `xlsx.rs`：读 `patch::read_date1904`，写 `book.set_date1904`（与基准不同才写）。
5. `xls_read.rs` / `xls_write.rs`：`read_date1904` 扫 `DATEMODE`；`set_datemode` **就地改**
   骨架里已有那条记录（追加会让读端先撞上 0）。
6. `style.rs`：`format_date_in/format_value_in(sys,..)`；星期几按体系分别算。
   应用 5 处 `format_value` 全改 `format_value_in(self.wb.date_system, ..)`。
7. `pivot.rs` 三处调用（`compute`×2、`row_values`）在 app 里用 `with_date_system` 包住。
8. `charts.rs`：`read_ref_in` 拆出带 `styles+sys` 版本（分类/名称仍用显示文本）；
   **值轴改用 `read_ref_numbers` 取原始数值**。
9. `clipboard_xmlss.rs`：新增 `iso_to_serial(sys, iso)`，按目标簿重算序列号，
   **保留时间小数**（`T12:00:00` → +0.5）。
10. `app/main.rs`：粘贴 Excel/WPS 的 XMLSS `DateTime` 走 `iso_to_serial`，
    不再落成文本；无数字格式时补 `yyyy-mm-dd`。
11. **实机验收中发现的写包缺陷**：`xlsx.rs` 写字体时无条件 `set_size(0)`、`set_underline("none")`、
    `set_strikethrough(false)`，umya 会写出 `<sz val="0"/>`、`<u val="none"/>`、`<strike val="0"/>`，
    这些不合 OOXML 约束，**Excel 16.0 直接拒绝打开整个文件（COM 0x800A03EC）**，WPS 能开。
    改为只在真正设置过时才写。回归测试断言 styles.xml 里不出现这三个值。
    （这是"自己的读端能读 ⇒ 认定没问题"的反例。）

六、跨簿复制的转换规则（不是"所有数值加减 1462"）
------------------------------------------------
- 从 Excel/WPS 复制日期：XMLSS 的 `ss:Type="DateTime"` 是 **ISO 时间戳**，不是序列号。
  落格时按**目标簿的日期体系**重算：1904-01-02 → 1904 簿 1、1900 簿 1463；
  时间部分保留（`T12:00:00` → +0.5 天），否则中午会变午夜。
- 从 Excel/WPS 复制普通数字：`ss:Type="Number"` 原样落格，**不做任何偏移**（有断言）。
- 本应用复制出去：剪贴板是显示文本（日期就是 `1904-01-02` 这样的文本），
  Excel 会按自己的体系识别成日期，不存在"被我们加了 1462"的路径。
- `.xls ↔ .xlsx`：同一 `Workbook.date_system`，写端按体系写 flag/DATEMODE，序列不动。

九、原要求路径补证（2026-11-13 02:48，本轮新增）
------------------------------------------------
要求路径：本项目导入 1904 夹具 → 本项目改**非日期格** → 本项目另存到**新路径** →
Excel 与 WPS 各自打开这个新文件。

执行链（Rust，`date_system::make_c04_export_fixture`，`#[ignore]`）：
1. 本项目写出夹具 `seed_1904.xlsx` / `seed_1900.xlsx`（A1=1，格式 `yyyy-mm-dd`，DateSystem 1904/1900）；
2. `xlsx::load` 导入（断言体系与 A1 不漂）；
3. 改 B2=7（非日期格）；
4. `xlsx::save` 另存为**新路径** `export_1904.xlsx` / `export_1900.xlsx`；
5. 自检读回：体系、A1=1、B2=7、显示 `1904-01-02` / `1900-01-01`。
命令：`cargo test -p sheetcore --test date_system -- --ignored make_c04_export_fixture --nocapture`
结果：1 passed；输出两行 EXPORT（system/file/A1/display/B2/fmt）。

实机（`scratch/c04_export_probe.ps1` 打开导出文件，只读，不改动）：

| 软件 | 文件 | date1904 | A1 值 | A1 显示 | B2 值 | B2 显示 |
|---|---|---|---|---|---|---|
| Excel 16.0 | export_1904.xlsx | True | 1 | 1904-01-02 | 7 | 7 |
| WPS 12.0 | export_1904.xlsx | True | 1 | 1904-01-02 | 7 | 7 |
| Excel 16.0 | export_1900.xlsx | False | 1 | 1900-01-01 | 7 | 7 |
| WPS 12.0 | export_1900.xlsx | False | 1 | 1900-01-01 | 7 | 7 |

产物：`implementation-evidence/c04-probe/export/{seed_1904.xlsx,seed_1900.xlsx,export_1904.xlsx,export_1900.xlsx,probe-c04-export.json}`
（JSON 含时间、机器名、版本、四个软件的逐项读数）。

这一路径与第六节旧探针的区别：旧探针是「本项目造文件 → Excel 打开并另存」，
新探针是「本项目导入 → 本项目改非日期格 → 本项目另存新路径 → 两个软件打开**本项目另存的文件**」，
后者才是原要求的验收方向。

十、应用层粘贴链路（本轮新增行为测试）
------------------------------------
`crates/app/src/edit_regression_tests.rs::xmlss_datetime_pastes_into_each_date_system_with_time_and_plain_numbers`
（`cargo test -p app --bin app xmlss_datetime_pastes`，1 passed）

同一份 XMLSS 文本（`DateTime 1904-01-02T12:00:00` + `Number 1234.5` + `String 文本`，带
`NumberFormat yyyy-mm-dd hh:mm`）走完整应用路径：
`clipboard_xmlss::parse` → `office_clipboard::convert_block` → `SheetApp::paste_office_block`
（真实粘贴处理，不是只测 helper），分别粘进 1904 与 1900 目标簿：

- 1904 簿：A1 = 1.5；1900 簿：A1 = 1463.5；两者差 **1462.0**；
- 小数部分都是 0.5（时间 12:00 保留，没被截成整数天）；
- 普通数字 1234.5 在两个簿完全一致，文本「文本」一致；
- 两个簿落格后都带 `yyyy…hh` 日期时间格式；
- 显示：两个体系对同一时刻都显示 `1904-01-02 12:00`（序列号差 1462，基准也差 1462）。

变异：把 `iso_to_serial(self.wb.date_system, …)` 改成固定 `D1900` → 该测试失败
（`left: 1463.5, right: 1.5`），源码已还原。
