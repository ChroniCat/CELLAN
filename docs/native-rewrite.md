# 原生重写：路线与里程碑

目标：不基于 Chromium 的桌面表格客户端，直接读写内网共享盘（SMB/UNC）上的 `.xlsx`，同一文件多人同时编辑、实时同步。

## 技术栈（已定）

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Rust | 内存占用低、无 GC、单二进制分发 |
| 界面 | `egui` + `eframe`（wgpu 后端） | 原生绘制，无 Chromium；实测内存见下方"实测数字" |
| 表格渲染 | 自绘虚拟化网格（只画可见区） | 100 万单元格不卡 |
| 单元格模型 | 稀疏存储 `HashMap<CellRef, Cell>` | 空表不占内存 |
| xlsx 读写 | `calamine`（读）+ `umya-spreadsheet`（写，保留样式） | 先求能打开/保存不损坏 |
| 公式 | 自研解析器 + 求值器，先 30 个函数 | 可控、可对拍 |
| 协作 | `yrs`（Yjs 的 Rust 实现）+ 自建传输 | CRDT，断线合并 |
| 传输 | TCP/WebSocket，局域网直连 | 一个进程既当客户端也能当宿主 |

### v1.31 插删行列后自动改写公式引用 ✅ 2026-11-07

之前插行删行只搬格子，公式里的 `A1`、`SUM(A1:A10)` 全指着老位置——一插行就错位。
这是结构性改动最要命的一环，现在按 Excel 的规则补上。

`crates/core/src/refs.rs` 是一个**公式引用扫描器**，不是字符串替换：

- 跳过字符串字面量：`="A1 不是引用"&A1` 里的 `A1` 不动，只改动后面那个。
- 跳过函数名：`LOG10(100)` 里 `LOG10` 后面跟着 `(`，不当引用。
- 认得引号表名：`'我的 表'!A1`；带表名的引用只在「被改的那张表」上平移，
  本表引用也只在「公式所在的表 == 被改的表」时平移。
- 支持单元格、区域、整列 `A:C`、绝对/相对混用（`$A1`、`A$1`、`$A$1` 都平移）。
- 绝对引用**照样**平移（`$A$1` 插 1 行变 `$A$2`），和 Excel 一致。

删除的语义按区间收缩处理，这比「沾边就 #REF!」实用：

| 原公式 | 删掉第 2 行 | 结果 |
|---|---|---|
| `=A1` | — | 不变 |
| `=A2` | 整格被删 | `=#REF!` |
| `=A3` | 下面上移 | `=A2` |
| `=SUM(A1:A5)` | 只删中间一行 | `=SUM(A1:A4)` |
| `=SUM(A2:A5)` | 整段都在删除区 | `=SUM(#REF!)` |

生效范围：单元格公式、条件格式里的公式规则、数据验证的公式，
以及**跨表引用**（改「数据」表，其他表里 `=数据!A1` 一起改）。
入口是 `structural::apply_structural_wb`，界面的插入/删除与协作收到的结构改动都走它。

验证：`refs` 模块 8 个单测（插行/删行/整列/字符串/函数名/表名限定/区间收缩/纯数字），
`structural_edit` 3 个集成用例（插行改公式、删行变 #REF!、跨表跟随）；
界面上用 `formula.xlsx`（B1 `=SUM(A1:A3)`、C1 `=A1*10`）在顶部插 2 行，
dump 显示 B3=6、C3=10，公式文本读出来是 `=SUM(A3:A5)` 和 `=A3*10`。

**踩坑**：dump 只在有重绘时落盘，窗口静止后应用不再请求重绘，
`SC_DUMP_AT` 等不到那一帧——加了「有 dump 待写就保持 100ms 刷新」。

### v1.26 传输加密 ✅ 2026-11-07

之前房间口令只防误连，内容全是明文 JSON，抓包就能看见表格数据。

- `crates/core/src/wire.rs`：ChaCha20 流加密 + HMAC-SHA256（encrypt-then-MAC）。
  本机离线拿不到 rustls/ring，所以自己实现；**对上的是 RFC 8439 的官方测试向量**
  （§2.3.2 块输出、§2.4.2 加密结果），不是「看起来能跑」。
- 密钥：`SHA256("sheetcore-wire-v1" ‖ salt ‖ 口令)`，再分别展开加密钥与认证钥。
  宿主每次连接生成新 salt，随 `ChallengeSalt` 明文下发。
- **方向位**：两个方向若用同一 nonce，密钥流会重复（等于把两段明文异或在一起）。
  所以 nonce 里带方向字节，收发各一个计数器，重放/乱序直接拒。
- 帧格式：`base64(方向 ‖ 计数器 ‖ 密文 ‖ tag)`。口令为空时保持明文（局域网内网自选）。
- 口令不对时宿主回一句明文「口令不正确」再断开；客户端也接受这一帧明文提示。
- 验证：RFC 向量 2 个；会话往返、篡改一字节必须拒、重放必须拒、错口令必须拒；
  双进程同口令 `ops: 18` 正常同步；裸 socket 实测第一帧是 `ChallengeSalt` 明文、
  随后发明文 Hello 直接被断开；错口令客户端 0 条 ops。

**踩坑**：加密接反过一次——宿主写线程可能在挑战帧之前就收到密钥，
按「有没有会话」判断要不要加密会把挑战帧也加密，握手直接失败。

### v1.13 LET 与嵌套 LAMBDA ✅ 2026-11-06

### v1.4 存储层紧凑化（行内有序向量） ✅ 2026-11-06

**先拆账再动手**：124 字节/格里只有 40 是 `Cell` 本体，约 56 是 hashbrown 槽位开销
（每条目 48 字节 + 控制字节 + 容量余量），剩下才是字符串分配。

所以第一刀砍的是存储结构，不是字符串：

`HashMap<CellRef, Cell>` → `HashMap<u32 行号, Vec<(u32 列号, Cell)>>`（行内按列升序，二分查找）

| 指标 | 之前 | 现在 |
|---|---|---|
| 内存（100 万格混合负载） | 124 字节/格 | **111 字节/格** |
| 152MB 文件全量重算 | 19.1 s | **14.1 s**（−26%） |
| 编辑一格（15k 格连带重算） | 60 ms | 69 ms |
| GUI 工作集 | 182–207 MB | **194 MB** |

重算变快是因为范围扫描变成了连续内存遍历（SUM 一个 1.5 万格区域不再跳哈希表）。

**为什么只降了 13 字节**：每行一个 `Vec` 意味着每行一次分配 + 容量余量（5 个格子通常预留 8 个），
再加上 `HashMap<u32, Vec>` 每行一个条目。实测下来这部分抵消了大半收益。

**结论**：字符串 arena 的收益比我先前估的小（40→32 字节/格 + 省掉 malloc 头，合计约 15–18 字节/格）。
要真正到 60 字节/格，需要**分页列式存储**（所有单元格放在大块 `Vec<Cell>` 里、按列分块），
那是存储层重写，不是加个 arena 能解决的。

## 实测数字（v0.1，2026-11-06）

同一台机器、同一个文件（sample.xlsx，14 个非空格）、启动后静置 7 秒测量。

注意：glow 依赖显卡 OpenGL 驱动；在某些远程桌面/无 GPU 环境会白屏（本项目在 RDP 会话里遇到过），需要探测失败时回退 wgpu 或软件渲染。

## 保存链的六个"Excel 判损坏"陷阱（v1.27 排查记录）

真实样本 `real100_extreme.xlsx`（106 MB / 21 表 / 418 万格 / 207 万公式）往返后 Excel 拒收。
用"单特性小样本 + Excel COM 自动打开"做二分，最终定位到六处，全部与**包结构**有关，
不是单元格内容的问题：

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 色阶条件格式判损坏 | `<cfvo>` 与 `<color>` 交错输出 | 先全部 cfvo、再全部 color |
| 2 | 数据验证判损坏 | `formula1/formula2` 写成属性 | 改子元素 |
| 3 | 无 CF 的文件也判损坏 | `dxfs` 为空仍重写 styles.xml | 为空直接返回原样 |
| 4 | 带图片判损坏 | `<a:prstGeom prst="">` 空值 | 统一补 `prst="rect"` |
| 5 | 带表格/批注判损坏 | umya 重写时丢 `<tableParts>`/VML | 未编辑的表整段沿用基准 XML |
| 6 | 大文件判损坏 | 见下 | 见下 |

大文件的六处连锁问题（每修一处都要重新用 Excel 验证）：

1. **工作表被搬家**：umya 一律写到 `xl/worksheets/`，原文件在 `xl/stress/worksheets/`；
   搬家后绘图、图表、打印机设置的相对引用全部失效。→ `rehome_sheets()` 把部件挪回基准路径。
2. **`[Content_Types].xml` 悬空 Override**：搬走后留下 15 条指向不存在部件的声明。
   → `prune_content_types()` + `rebuild_content_types()`（以基准为准重建，只保留实际存在的部件）。
3. **样式 count 对不上**：补 dxf 时 `<dxfs count="50">` 没跟着变 56。→ `normalize_styles_counts()`。
4. **工作表 rels 被抢**：两个目录下的同名表共用一个 rels 路径，后写覆盖前写，
   出现"表里有 `r:id` 但 rels 不存在"。→ `restore_base_sheet_rels()` 统一以基准为准（脏表除外）。
5. **共享字符串没有关系**：骨架沿用基准（内联字符串，无 sharedStrings 关系），
   改写过的表却按 `t="s"` 写 → Excel 解析不出字符串。→ `ensure_shared_strings_rel()` 补关系。
6. **编辑过的表被 umya 整张重写**，丢掉 `<sheetPr>`、绘图引用、扩展区。
   → `merge_sheet_data()`：只把 `<sheetData>` 换进去，其余骨架用基准的。

## B4 外部数据（v1.28）

这一项不是真正的 Power Query —— 没有 M 语言、没有查询折叠、没有多表连接。
做的是实际最常用的两件事，并且**刷新能力随文件走**：

| 能力 | 说明 |
|---|---|
| 导入 CSV/TSV | 自动识别分隔符，数字转数值，`"a,b"` 引号里的分隔符不切 |
| 刷新 | 源文件改了点一下重读；行数列数变化一并更新 |
| 从另一张表取数 | 菜单「数据 → 从另一张表取数…」，填 `销售!A1:C100` |
| 持久化 | 数据源存在工作簿自定义名称 `_sc_src_N` 里（字符串常量），
重开文件后仍可刷新；Excel 打开只多几个名字，不影响计算 |

无界面自检 `SC_B4=1`：

```
[B4] 已导入 3 行 × 3 列（import.csv）
[B4] 第2行 ["张三", "研发", "100"]
```

已知边界：
- CSV 路径是绝对路径；换机器/换盘符后刷新会失败（会提示，不会静默清空）。
- 不支持 Excel 的 QueryTable 部件（Excel 里看不到"查询"面板），只保证文件本身合法可开。
- 跨表取数是值复制，不保留公式引用关系。

## B4 升级：真·Excel 查询表（v1.30）

之前只把 CSV 读进单元格，数据源信息存在自定义属性里。现在导入的 CSV 会同时挂成
**Excel 原生 QueryTable**——打开「数据 → 查询和连接」能看到这条查询，右键就能刷新，
刷新走的是 Excel 自己的文本驱动，不经过我们的代码。

实现要点（照着 Excel 2016 实际写出的文件对齐）：

| 部件 | 作用 |
|---|---|
| `xl/connections.xml` | 连接定义：`type="6"`（文本文件）、`textPr@sourceFile`、`codePage="65001"` |
| `xl/queryTables/queryTableN.xml` | 查询表本体，靠 `connectionId` 挂到连接 |
| 工作表 rels | 一条 `queryTable` 关系（工作表 XML 里**没有**对应元素，Excel 只认 rels） |
| `xl/_rels/workbook.xml.rels` | 必须有一条 `connections` 关系，缺了 Excel 直接打不开 |
| workbook.xml | 一条同名定义名称指向目标区域（`localSheetId` 必填） |

踩到的三个坑：

1. **`<textFields>` 不能省**：没有表头时我以为可以省略，结果 Excel 判文件损坏。
   实测 Excel 无论有没有表头都写 `<textFields><textField/></textFields>`。
2. **数据源不能塞进 definedNames**：和查询表自己的同名定义名称冲突，Excel 拒收。
   改存 `docProps/custom.xml`（自定义文档属性，Excel 规范位置）。
3. **`workbook.xml.rels` 缺 connections 关系**：部件齐全但 Excel 打不开。

验证（Excel COM）：

```

  connection=TEXT;<workspace>\work\import.csv
  Refresh OK A2=赵六     # 改 CSV 后刷新，Excel 自己拉到新值
```

## 并行加载（v1.33）

`load` 改成按工作表切分多线程：每个线程自己开一个 calamine reader，
各自解析一组表，产出「原始单元格 + 样式 + 公式」三组数据；
样式回主线程统一 `intern`（样式表是共享可变状态，不能并发写）。

实测（106 MB / 21 表 / 418 万格）：

|---|---:|---:|---:|
| 首屏读入 | 8.22 s | 5.47 s | **4.76–4.96 s** |

## 会话发现：双击即入（v1.34）

原来的协作要手动填 `192.168.1.20:7878`。现在改成"文件旁边放一张占用卡"：

- 宿主开始共享时，在**工作簿同目录**写 `.~sheetflow-<文件名>.lock`，
  内容是 `host=IP:端口 / user / machine / pid / beat`
- 每 5 秒刷新 `beat`；别人打开同一个文件先读这张卡，20 秒内新鲜就直接连
- 卡片过期（对方崩溃或断电）→ 打开者**自动接管**，把卡换成自己的地址
- 正常退出时撤卡（`Drop`），不会给下一位留下死地址
- 不写广播：用户的实际场景是 Z: 盘共享目录，跨网段广播到不了，但目录两边都能写

实测（同一台机上两个进程模拟两位同事）：

## 原子保存 + 谁在编辑（v1.35）

**原子保存**：`save_atomic` 先写同目录临时文件 `.~<名>.saving-<pid>`，
成功后再 `rename` 覆盖目标。SMB 共享盘上直接写目标，断网或对方占用会留下半截文件；
同一卷内 rename 是原子的，别人要么看到旧文件、要么看到完整的新文件。
目标被 Office 占用导致 rename 失败时，临时文件会保留并在状态栏说明路径，不谎报成功。

**谁在编辑**：窗口标题实时反映会话状态：

```
share_test.xlsx · 2 人协作（example-user） - Sheets Native
share_test.xlsx * · 已加入协作会话 - Sheets Native
share_test.xlsx · 张三 正在编辑 - Sheets Native     ← 没连上，但占用卡在
```

- 宿主：`已共享，等待同事加入` / `N 人协作（名字…）`
- 成员：`已加入协作会话`
- 未连接但占用卡新鲜：`张三 正在编辑`
- 有未保存改动时文件名后加 `*`

同一台机器跑两个进程时名字相同，标题里的成员按站点号区分，不会把自己算进去。

## 单实例 + 文件关联（v1.36）

**单实例（同文件）**：第一个实例在 `127.0.0.1:48765` 监听；再次双击**同一个文件**时，
新进程连上去问"你开的是不是这个文件"，主实例后台线程比对路径（canonicalize 后比较），
是就回 `yes`、新进程打印"已在此窗口中打开"并退出。

- 比对放在后台线程：窗口最小化或被遮挡时 egui 不重绘，交给 UI 线程回话会超时
- **不同文件照常开新窗口**：没有标签页之前，强行复用窗口会顶掉当前文档，
  万一有未保存改动就是数据事故
- 用 TCP 回环而不是命名互斥量：不需要 FFI，进程退出端口自动释放，不会留"幽灵实例"

实测：

```
第二次打开同一文件 → 已在此窗口中打开（退出码 0）
第二次打开不同文件 → 自己开窗口（超时 124，即仍在运行）
```

- 菜单「文件 → 设为默认打开方式」：再把 `.xlsx` 的默认值指过来；
  Windows 10/11 仍可能要求用户确认一次，这是系统策略，绕不过
- 命令行 `--register-assoc` / `--set-default`：打包脚本和安装器可直接调用

## 保存历史 / 自动更新 / 最近文件（v1.37）

**1. 历史版本**（`sheetcore::backup`）

每次 `save_atomic` 覆盖前，把旧文件复制到工作簿旁边的
`.~sheetflow-history/<文件名>/<时间戳>-<文件名>`，默认保留 10 份，超出删最旧。

- 放同目录而不是本机：网盘上的工作簿换个人打开也能翻到历史
- 同一秒内保存两次会加序号，不会互相覆盖
- 菜单「文件 → 历史版本…」列出可用版本，点一下就在编辑器里打开（另存为新文件即保留）
- 单测覆盖：首次保存不留空历史、留存的字节与原文件一致、只保留最近 N 份

**2. 自动更新**（`app::update`）

共享目录发版，不需要更新服务器：

```
Z:\软件\Sheets\
  manifest.txt        version=1.38 / exe=SheetsNative-1.38.exe / sha256=...
  SheetsNative-1.38.exe
```

启动时或菜单「文件 → 检查更新…」比对版本号；有新版就复制到
`%LOCALAPPDATA%\SheetsNative\updates\pending-<版本>.exe`，**校验 SHA-256**，
通过后写一个 `apply-update.cmd`，等本进程退出再替换 exe 并重启。
哈希不符直接丢弃并报错——共享盘上半截复制很常见，宁可装不上也不装坏的。

实测：

```
[update] 发现新版本 99.0，已下载并校验；关闭窗口后自动替换并重启
updates 目录：pending-99.0.exe
```

**3. 最近文件 / 启动页**（`app::recent`）

`%LOCALAPPDATA%\SheetsNative\recent.txt` 存最近 12 个路径（新的在上，去重）。
不带文件参数启动时显示启动页：最近文件列表（文件名 + 所在目录）、打开文件、新建空白。
列表只显示仍然存在的文件，网盘断开或文件被删会自动剔除。

## 多标签（v1.38）

一个窗口里开多个工作簿。

## 从 Excel 粘贴：带格式和合并（v1.39）

Excel 复制单元格时，剪贴板上同时放了纯文本(TSV)、HTML 和几种二进制格式。
之前只读 TSV，所以值对了、格式没了。现在优先读 **HTML Format**：

- 解析 `<table>` 的 `<tr>/<td>`，认 `colspan/rowspan` → 合并单元格
- 内联样式映射到我们的格式：`font-weight:700/bold` → 粗体、`font-style:italic` → 斜体、
  `background-color` / `background` → 填充、`color` → 字色、`text-align` → 水平对齐、
  `border` → 细实线边框（颜色取 `border-color`，缺省黑）
- 颜色支持 `#rrggbb`、`rgb(r,g,b)` 和几种命名色
- 一次粘贴 = 一个撤销事务；超过 20 万格自动退回纯文本粘贴
- 纯文本粘贴（Ctrl+Shift+V）仍走原来的 TSV 路径

直接调 Win32（`OpenClipboard` / `GetClipboardData` / `GlobalLock`），
没有为几十行 API 引入 windows crate。

实测（真实系统剪贴板，从 PowerShell 写入 Excel 风格的 HTML）：

```
[paste] 读到表格 2 行 × 3 列
[paste] 成功=true A1="合计" 粗体=true 填充=Some([255, 255, 0]) 合并数=1
```

**公式不在可读格式里**：Excel 的 HTML 只有显示值，二进制格式才带公式。
所以从 Excel 粘过来是"值 + 格式 + 合并"，公式保留要等以后做 Biff 解析。

## v1.40 公式量化对齐（2026-11）

用 Excel 缓存值做基准逐格比对 `examples/verify_formulas.rs`，106 MB / 21 表 / 206.9 万公式：

| 阶段 | 一致率 | 不一致 |
|---|---:|---:|
| 初始 | 52.36% | 878,073 |
| 带引号表名 `'表名'!A1` | 97.86% | 39,358 |
| 公式实体 `&gt;`/`&lt;`（GeneralRef 被丢弃） | 99.83% | 3,060 |
| ROUND 15 位有效数字 | **99.9992%** | **15** |

四个坑：
1. 词法不认 `'表名'!$B$7`，20 万个格直接 #VALUE!。
2. 共享公式子格只有 `si`，要按主格文本平移；`shift_refs` 只动相对部分。
3. quick_xml 把 `&gt;` 发成 `Event::GeneralRef`，落在 `_ => {}` 里被丢掉，比较运算符整片消失（`A1>5` 变 `A15`）。
4. Excel 算术只保留 15 位有效数字；`ROUND(x*100,0)` 前先 `round_sig15`，否则 9745.005 会舍成 9745.00。

剩余 15 格是真功能缺口：结构化引用 `SUM(表[列])` 4 格、动态数组溢出 8 格、LET/LAMBDA 3 格。

### v1.41 三个模块

- **动态数组溢出**：文件里 `t="array" ref` 的覆盖区先登记成溢出区，重算时旧结果不挡住新结果；`LET(x, A6:A11, …)` 的 x 绑定整块数组而不是左上角。
- **结构化引用**：表部件按工作表 rels 相对路径解析（`xl/stress/worksheets/` + `../tables/table1.xml`），此前写死 `xl/tables/`，自定义目录的文件里表根本读不到，`SUM(表[列])` 全 #VALUE!。
- 一致率 99.9992% → **99.9998%**（剩 4 格：交集运算符、定义名称、LAMBDA 立即调用、S1 单格）。

### v1.42 收尾三格

- **共享公式（calamine 路径）**：解析库给子格的是主格原文，未按位移改；按 XML 的 si 组重新推导并覆盖。S1 G59 由"失败"变"通过"。
- **TEXT 前导零**：`TEXT(12.3,"000.00")` 之前给 "12.30"，整数段的 0 是"至少几位"，现在补零到 "012.30"。
- **交集运算符**：`A1:A2 B1:B2` 的空格是 intersection，无重叠报 `#NULL!`（之前 #VALUE!）。
- **LAMBDA 立即调用**：`LAMBDA(x,x*x)(7)` = 49（解析器支持函数值后直接跟实参）。
- 最终：**一致率 99.99995%**，184 万公式格只剩 1 格不一致，且该格是样本缓存值写错（缓存 #NAME?，真 Excel 算 49）。

### v1.43 真实语料

拿两张真实业务表跑量化：

真实表暴露的问题（压力测试样本里没有）：

### v1.45 压力样本 100% 的真相

最后那 1 格是 `=LAMBDA(x,x*x)(7)`。拿本机 Excel 实测（COM，16.0 Build 20326）：


### v1.46 内嵌字体三层（2026-11）

以前只有「粗体/字号/字色」，字体名进不了模型，存盘必然丢。这轮把字体做成引擎里的一等字段，
配内嵌字形，界面可选可改，三层都对得上。

**引擎（crates/core）**

- `CellStyle.font`（空串 = 默认字体）。`StyleTable` 的哈希是手写的，font 也算进去；
  `PartialEq` 是 derive 的，自然覆盖新字段——两者一起保证宋体/黑体不会被 intern 成同一个样式号。
- 读：`<font><name val="…"/>` 经 `normalize_font` 落进 `CellStyle.font`。
- 写：`font.set_name()`，umya 按字体分组生成 `<font>` 条目（同名同字号同色只留一条），
  同时把 `scheme` 置成 `none`——留着 `scheme="minor"` 的话 Excel 会拿主题字体盖掉名字。
- 归一表（中英双名互认）：宋体↔SimSun、黑体↔SimHei、微软雅黑↔Microsoft YaHei、
  等线↔DengXian、思源黑体↔Noto Sans SC、思源宋体↔Noto Serif SC、Inter、JetBrains Mono。
  认不出来的名字原样保留：渲染回退默认，写盘不改用户的选择。
- 条件格式 dxf 的 `<font><name val>` 双向都通了，命中时经 `Overlay.font` 交给渲染。
- 合并区域只画锚点那一格，整块跟着锚点样式（含字体）走；协作的 `StyleOp` 是整份
  `CellStyle` 的 JSON，font 自动带上；撤销记的是样式号，字体一起回滚。

**渲染（crates/app）**

- 内嵌四套子集注册成 `noto-sans / noto-serif / inter / mono`；
  自定义 family 有 `default / cjk-sans / cjk-serif / latin / mono`。
  界面默认 = Inter + 思源黑体（中文回退）；宋体族只挂思源宋体，连拉丁也用衬线，
  和黑体一眼能分开。
- 单元格按 `FontClass::key()` 选 family，未知字体回退 `default`；
  名称框与编辑栏用等宽，行号列标用 Inter。
- 原来那份 2.8 MB 的单套子集（`assets/cjk-subset.ttf`）退休，四套子集合计 5.4 MB。

**界面**

- 「开始」页与 Ctrl+1 对话框各一个字体下拉：内嵌四款 + 宋体/黑体/微软雅黑/等线
  （后四款映射到最接近的内嵌子集，选了一定有字形）。选中即走既有 `apply_style`：
  可撤销、能协作同步、下一帧就换字形。

**顺手修掉的「另存为丢样式」**

`save()` 原来先把 `wb.path` 改成目标路径，再让 `save(path, wb)` 拿它当基准文件。
目标是新路径时基准不存在，umya 从空白建表——整份文件只剩值，样式/字体/合并全丢。

### v1.50 公式写进 .xls（BIFF8 RPN 编译器）

上一版"另存为 .xls"遇到公式只能拒绝。这一版把公式真正编译成 BIFF 的字节码。

**形式**：BIFF8 不存公式文本，只存 RPN（逆波兰）记号流——操作数先入栈、运算符出栈计算。
`=A1+B1*2` 编成 `ptgRef A1 / ptgRef B1 / ptgInt 2 / ptgMul / ptgAdd`，括号和优先级在编译期
就没了。

**函数号不是猜的**：用 Excel 生成 62 条公式的样本，逐条读出 `iftab`。
（SUM=4、IF=1、VLOOKUP=102、CONCATENATE=336、IFERROR=255、TODAY=221……）
表在 `xls_formula.rs`，未收录的函数会明确报错而不是悄悄写错。

**记号细节**（都踩过）：

- 记号带"类"位：普通公式里引用写数值类 `ptgRef 0x44`、`ptgFunc 0x41`、`ptgFuncVar 0x42`；
- 引用的行列字在第 15/14 位带"相对"标志，`$B$2` 就是把这俩位清掉；
- 跨表引用 `T!A1` 用 `ptgRef3d 0x5A` + ixti，ixti 指向全局的 EXTERNSHEET 条目；
  因此要在全局流里补 SUPBOOK（自引用，cch=0x0401）和 EXTERNSHEET；
- 文本结果：FORMULA 的 8 字节缓存值写 `FF FF 00 …`，紧跟一条 STRING 记录；
- `grbit/chn` 全 0；`cce` 必须等于记号流长度。

**两个让 Excel 判"文件损坏"的坑**：

1. ROW 记录的 `grbit` 要 0x0140（自定义行高），并且记录体就是 16 字节——
   多写 4 字节 Excel 直接拒绝；
2. XF 里填充的写法：无填充是 `17=0x02, 18=0xC0`，实心是 `17=0x06, 18=调色板索引`，
   边框颜色是 `40 20 40 20`（不是四个 0x40）。

**验收**（Excel 16.0 COM，同一张发票）：

|---|---|---|

| D3 | `=TODAY()` | 一致 |
| E15 | `=E12+E13-E14` | 一致（59,350.00） |

**仍不支持**：数组常量、定义名称、跨工作簿引用、未收录的函数（都会报错说明，
不会静默降级成值）。

### 第八轮：三个已知限制的处理（2026-11-10 晚）

**1. 打开密码（ECMA-376 Agile）**

- 新增 `crates/core/src/crypto.rs`：AES-256-CBC + SHA-512，CFB 容器里写
  `EncryptionInfo` / `EncryptedPackage`，并补 Excel 必需的 `\x06DataSpaces`
  （Version / DataSpaceMap / StrongEncryptionDataSpace / Primary）。
- 派生细节：`H0 = SHA512(salt || UTF-16LE(pw))`，迭代 `H_i = SHA512(LE32(i) || H(i-1))`
  （序号在前，和 msoffcrypto 对齐）；三段 blockKey 分别派生验证器输入/验证器哈希/包密钥。
- 包分段 IV = `SHA512(keyDataSalt || LE32(block))[..16]`；`dataIntegrity` 写真实
  HMAC-SHA512（否则 Excel 判“加密类型不可用”）。
- 打开：`xlsx::load_with_password` 解密到临时文件加载，加载完立即删除；密码只留在内存。
- 保存：另存时先解密原文件当基准 → 写明文临时文件 → 加密回目标；没有长期明文落盘。
- UI：打开加密文件弹“需要打开密码”；文件→信息有“用密码加密…”/“取消打开密码”。
- Excel 实测：本程序生成的加密文件用 Excel+密码可打开（`A1=加密测试`），Excel 生成的
  加密文件本程序可解密；改一格另存后 Excel 仍能打开且 `A2` 保留。

**2. 插入/删除单元格改写公式引用**

- `refs::Shift` 增加 `row_filter`/`col_filter`，`allow()` 只在引用落在被移动的行/列范围内才改写。
- 新增 `structural::apply_cell_shift_wb`，`shift_cells` 在搬完值/样式后调用它；
  撤销键里补上全表公式格，撤销能一起还原引用。
- 测试：A1 插入下移后 `A3+1` → `A4+1`，删除后回到 `A3+1`；水平插删只动选中行。

**3. sharedStrings 富文本**

- `richtext::sst_runs` 解析 `<si><r><rPr>…</rPr><t>…</t></r></si>`，加载时按整段文字回填
  `Sheet.rich`（首见优先）；写入仍用 inlineStr，Excel 逐段格式可读。
- 实测：Excel 生成的 `sst_rich.xlsx` 载入为 2 段（第二段 16pt）；另存后 Excel 读
  `A1=红色加粗普通`、第 5 字 `16pt`，无修复提示。

仍不支持的：BIFF8（.xls）打开密码、证书加密（keyEncryptor=certificate）。
### 第九轮：大文件打开为什么卡（2026-11-10 深夜）

用 107 MB / 16 表 / 418 万非空格的 `lp2.xlsx` 做剖面（release + SC_LOAD_PROF）：

| 阶段 | 耗时 | 说明 |
|---|---|---|
| `xlsx::load` | 8.1–9.1 s | 其中并行解析+物化约 6.2 s，合并/版面等约 2.7 s |
| 找不到问题：整份 clone | 0.5–0.6 s | 为让界面先显示缓存值 |
| **全量重算** | **87.1 s** | 4.18 M 格里逐条递归求值，CPU 一直满 |
| 依赖图 | 6.8 s | 全表扫描公式、解析引用 |
| 峰值内存 | ~1.8 GB | 4.18 M 格本身约 450 B/格 |

结论：卡顿主因不是“读文件”，而是**打开后自动全量重算 87 秒**，期间后台线程把 CPU 吃满，
同时整份工作簿还在内存里复制了一份。

处理：

- **大文件不再自动全量重算**：`cells > 400k` 或 `formulas > 30k` 时直接用文件里的缓存值显示，
  状态栏提示“已打开大文件（显示缓存值）”。
- 依赖图改用**只含公式文本的轻量骨架**计算，不再 clone 整份工作簿；骨架算完即释放。
- “公式→重算全部”和 F9 改为后台任务：复制一份算完再替换，界面不冻结；期间有编辑则丢弃结果。
- 阈值可用 `SC_BIG_CELLS` / `SC_BIG_FORMULAS` 调，`SC_FORCE_RECALC=1` 强制老行为。

实测同一文件：缓存值 ~9 s 显示，依赖图 ~6 s 后台完成，不再出现 87 s 满 CPU；编辑/滚动可用。

仍存在的物理上限：107 MB 文件解析约 8 s、4.18 M 格常驻约 1.8 GB。要再快只能做按表惰性加载
或换更紧凑的存储（当前是每格一个堆分配的值/样式结构）。
### 第十轮：单元格文字不再越过列线

问题：长文本按 Excel 的“溢出显示”规则会跨过右侧空列，盖住列间竖线/边框，视觉上像文字压在表格上。

处理：

- 单行文本默认**裁剪在单元格矩形内**（水平、垂直都裁），不再跨列；超链接下划线同样裁剪。
- 视图 → 显示 → “文字溢出”可切回 Excel 默认的溢出行为（开着时仍只按行高裁剪，不会上下压行）。
- 富文本/自动换行本来就是按格子裁剪，保持不变。

`review.xlsx`（A20:F30 复制出的样本）截图确认：文字停在 A 列右边界，B 列竖线完整可见。
### 第十一轮：垂直对齐把文字顶出行

问题：A1 设成“底对齐”后，文字被画到 A1 下边框以下，看起来像掉进了 A2。

原因：旧代码把 `ty` 当成“文字中心”来用（`ty = 底边 - 4`），再交给居中对齐绘制，
文字下半截自然越过行线；顶部对齐同理会把上半截顶到行外。富文本 run 也有同样问题。

处理：单行与富文本都改成 **galley 顶边对齐**：

- 顶端对齐：`y = rect.top + 4`
- 底端对齐：`y = rect.bottom - 4 - 文字高度`
- 居中：`y = rect.center - 文字高度 / 2`

配合上一轮的单元格裁剪，文字不会再跑到相邻行。`apply_test.xlsx`（A1 宋体 11、底对齐、
行高 25）截图确认文字完整落在 A1 内。
### 第十二轮：修订记录“撤回没反应”

原因有两层：

1. 撤回成功/失败只在**状态栏**提示，状态栏被修订窗口挡住 → 看起来没反应。
2. 只改格式的记录，冲突检查只比对了值和公式，没比格式；文件重开后当前格式和记录里的
   `after_style` 不一致也会被当成“可撤回”，实际写回时没有差异 → 静默空转。
   反向问题也存在：字体名/垂直对齐在读写盘后会被规范化（空字体名、valign 0↔3），
   严格比较会误判冲突。

处理：

- 修订窗口内新增结果行：成功绿色“已撤回…（记录已刷新）”，失败红色说明原因；
  成功后从磁盘重新读取日志，列表里会多一条“撤回修订”。
- 冲突检查同时比对值和格式；格式比较用 `style_visual_eq`：空字体名视为默认字体，
  `Some(白)` 与 `None` 视为同底色，忽略 valign 的读写规范化，其余字段严格比对。
- 有冲突时不再写回，只提示“有 N 格在它之后又被改过”。

验证：合成一份“宋体→黑体”的修订文件，撤回后 Excel 回读 `A1 font=黑体`，日志从 1 条变 2 条；
冲突样本显示红色提示；`revision_revert_restores_font` 回归通过。
### 第十三轮：网盘文件默认静默共享

目标：不需要点“共享”，也不需要填地址——网盘上能看到这个文件、装了本软件的人，打开就自动进同一个会话。

处理：

- **自动选主**：打开网盘/共享目录（UNC 或映射网络驱动器，`GetDriveTypeW == DRIVE_REMOTE`）上的文件时，
  若没有新鲜的占用卡，就静默 `start_host()`，占用卡和选主文件写在文件旁边。
- **自动加入**：占用卡新鲜时直接 `net::join`，状态栏/标题只做告知，不弹框。
- **选主竞争**：`claim_election` 用 `create_new` 抢 `.~sheetflow-<文件名>.elect`；抢不到就轮询占用卡
  最多 2 秒再加入，避免两人同时打开时开出两个房间。宿主启动后再读一次卡，若被别人后写就退出宿主去加入。
- **自动接任**：占用卡过期（20 秒无心跳）时，下一个打开的人自动接管并重开房间。
- 审阅 → 共享 增加“自动共享”开关（默认开）；`SC_AUTO_SHARE=1` 可强制对本地文件也自动开房（测试用）。
- 退出/正常关闭时撤卡并删除选主文件；异常退出靠 15–20 秒过期自动恢复。

限制：有打开密码的房间不能静默加入（别人拿不到口令时会在状态栏提示，需手动填）；
OneDrive 这类“本地同步文件夹”不是网络驱动器，不会被判定为网盘路径；
首次监听端口时 Windows 防火墙需要放行一次，这个做不到完全静默。

`已自动加入 example-user 的编辑会话（192.0.2.232:7878）`，标题变为“已加入协作会话”，并收到初始操作。

### 第二十二轮：错误检查、单变量求解、模拟运算表

**错误检查（公式 → 公式审核 → 错误检查）**

- `crates/core/src/errors.rs`：扫一张表，认出 8 类错误值 + 「数字存为文本」。
- 关键细节：模型里的错误是 calamine 的 Debug 简写（`#Div0` / `#NA` / `#Name` / `#Value` / `#Ref`…），
  **不是** Excel 的显示文本。只按 `#DIV/0!` 匹配会一条都扫不到；现在两种写法都认。
- 「数字存为文本」没法按值判断——加载器会把看起来像数字的文本直接转成数字，
  所以改成「数值 + 单元格格式是 `@`」来识别（`scan_wb` 带样式）。
- 对话框：地址 / 内容 / 中文说明三列，点地址跳到那个单元格；有「重新检查」。
- 绿三角：错误格左上角画 5px 三角，按 `(doc_gen, wb_epoch)` 缓存——只用 doc_gen 的话，
  首次计算发生在文件装载完成之前，缓存永远是空的。三角要画在最后（边框之后），否则被文字盖住。
- 验收：造 5 个问题（A3/B3 `#DIV/0!`、B2 `#N/A`、B4 `#NAME?`、B1 文本格式的 123），
  对话框列 5 条，按像素找 (40,160,40) 确认 5 个格子都有绿三角。

**单变量求解（数据 → 模拟分析）**

- 割线法 + 区间二分兜底，最多 60 次；每次只改可变格、按依赖图重算受影响公式（`recalc_dirty`）。
- 依赖图必须**现建**：小文件装载后 app 里的 `deps` 可能还是空的，拿它重算等于什么都不算，
  求解会一直读到同一个值，割线法最后跳到几千。
- 失败时把可变格恢复原值；成功时记一条撤销事务。
- 验收：A1=100、A2=`=A1*1.2`，求 A2=150 → 解出 A1=125；另存后文件里 `<v>125</v>`。

**模拟运算表（列式单变量）**

- 布局按 Excel 的约定：公式在结果列**上方一格**（选区内不包含公式格），选区内第一列是输入值、第二列放结果。
- 每个输入值代入输入格 → 重算 → 把公式格当时的值写成静态数字；跑完把输入格恢复原值。
- 验收：B2:B4=2/3/4，C1=`=$A$1*$A$1`，输入格 A1 → C2:C4 = 4/9/16，A1 回到 100。

**顺手修掉的保存 bug**

- `xlsx.rs` 以前只给**外部引用**公式写缓存值，其它公式格沿用基准文件里的旧 `<v>`：
  改了输入格、公式格重算之后，文件里留的还是旧数字（Excel 要重算一次才对，别的阅读器直接读错）。
  现在所有公式格都按模型里的当前值写 `<v>`；错误值（内部 `#Div0` 这类简写）不写缓存，交给 Excel 重算。
- 这正是单变量求解第一次「解对了但存下来还是旧值」的原因。

测试钩子：`SC_OPEN_DIALOG=errors|goal|dtable`、`SC_GOAL=目标格,可变格,目标值`、`SC_DTABLE=输入格`（配 `SC_SEL`/`SC_SEL2`）。

### 第二十五轮：核实「加表后保存丢表」——是误判，并补上回归测试

上一轮记录过一条结论：「新增工作表再存回原文件会把原表挤掉」。这一轮按它写复现测试时发现**结论是错的**。

**误判怎么来的**：用 `<sheet name="([^"]+)"` 这个正则去数 workbook.xml 里的表。
而 Excel/umya 写出来的第一个表是 `<sheet sheetId="1" r:id="rId1" name="Sheet1"/>`——
`name` 排在 `sheetId`/`r:id` 后面，正则匹配不到，于是「只看到一个表」被当成「表丢了」。
同一份文件用我们自己的加载器读，两张表都在，`native-sheet-5-0.xml` 也正常。

**做法**：

- 新增 `crates/core/tests/add_sheet_save.rs`：加表后「原地保存」「另存为」「save_atomic」「插在中间」
  四种路径各一条断言，其中一条用 Excel 存的基准文件（`tests/data/two_sheets.xlsx`，带 calcChain 与 x14 扩展）。
- 新增排查用 `crates/core/examples/addsheet_probe.rs`：加载 → 加表 → 另存 → 用**我们的加载器**回读并打印表名。
  以后判断「表/部件有没有丢」一律走它，不再靠正则数 XML。
- 方案摘要恢复成 Excel 的行为：新建「方案摘要」工作表。实测 A1=10/B1=20/C1=`=A1+B1`、方案「低」，
  摘要生成后另存 → 回读两张表 → Excel COM 打开 `sheets=2`、摘要 A1=「方案摘要」，无「已修复」。

**教训**：OOXML 的属性顺序不固定，任何「数元素」的检查都要么用解析器、要么用自家加载器回读；
正则只适合在属性顺序已知的、由我们自己写出的片段上做确认。
