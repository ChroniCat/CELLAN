# 原生重写：路线与里程碑

目标：不基于 Chromium 的桌面表格客户端，直接读写内网共享盘（SMB/UNC）上的 `.xlsx`，同一文件多人同时编辑、实时同步。

## 技术栈（已定）

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Rust | 内存占用低、无 GC、单二进制分发 |
| 界面 | `egui` + `eframe`（wgpu 后端） | 原生绘制，无 Chromium；实测内存见下方"实测数字" |
| 表格渲染 | 自绘虚拟化网格（只画可见区） | 100 万单元格不卡 |
| 单元格模型 | 稀疏存储 `HashMap<CellRef, Cell>` | 空表不占内存 |
| xlsx 读写 | `calamine`（读）+ `umya-spreadsheet`（写，保留样式） | 先求能打开/保存不损坏 |
| 公式 | 自研解析器 + 求值器，先 30 个函数 | 可控、可对拍 |
| 协作 | `yrs`（Yjs 的 Rust 实现）+ 自建传输 | CRDT，断线合并 |
| 传输 | TCP/WebSocket，局域网直连 | 一个进程既当客户端也能当宿主 |

### v1.31 插删行列后自动改写公式引用 ✅ 2026-11-07

之前插行删行只搬格子，公式里的 `A1`、`SUM(A1:A10)` 全指着老位置——一插行就错位。
这是结构性改动最要命的一环，现在按 Excel 的规则补上。

`crates/core/src/refs.rs` 是一个**公式引用扫描器**，不是字符串替换：

- 跳过字符串字面量：`="A1 不是引用"&A1` 里的 `A1` 不动，只改动后面那个。
- 跳过函数名：`LOG10(100)` 里 `LOG10` 后面跟着 `(`，不当引用。
- 认得引号表名：`'我的 表'!A1`；带表名的引用只在「被改的那张表」上平移，
  本表引用也只在「公式所在的表 == 被改的表」时平移。
- 支持单元格、区域、整列 `A:C`、绝对/相对混用（`$A1`、`A$1`、`$A$1` 都平移）。
- 绝对引用**照样**平移（`$A$1` 插 1 行变 `$A$2`），和 Excel 一致。

删除的语义按区间收缩处理，这比「沾边就 #REF!」实用：

| 原公式 | 删掉第 2 行 | 结果 |
|---|---|---|
| `=A1` | — | 不变 |
| `=A2` | 整格被删 | `=#REF!` |
| `=A3` | 下面上移 | `=A2` |
| `=SUM(A1:A5)` | 只删中间一行 | `=SUM(A1:A4)` |
| `=SUM(A2:A5)` | 整段都在删除区 | `=SUM(#REF!)` |

生效范围：单元格公式、条件格式里的公式规则、数据验证的公式，
以及**跨表引用**（改「数据」表，其他表里 `=数据!A1` 一起改）。
入口是 `structural::apply_structural_wb`，界面的插入/删除与协作收到的结构改动都走它。

验证：`refs` 模块 8 个单测（插行/删行/整列/字符串/函数名/表名限定/区间收缩/纯数字），
`structural_edit` 3 个集成用例（插行改公式、删行变 #REF!、跨表跟随）；
界面上用 `formula.xlsx`（B1 `=SUM(A1:A3)`、C1 `=A1*10`）在顶部插 2 行，
dump 显示 B3=6、C3=10，公式文本读出来是 `=SUM(A3:A5)` 和 `=A3*10`。

**踩坑**：dump 只在有重绘时落盘，窗口静止后应用不再请求重绘，
`SC_DUMP_AT` 等不到那一帧——加了「有 dump 待写就保持 100ms 刷新」。

### v1.26 传输加密 ✅ 2026-11-07

之前房间口令只防误连，内容全是明文 JSON，抓包就能看见表格数据。

- `crates/core/src/wire.rs`：ChaCha20 流加密 + HMAC-SHA256（encrypt-then-MAC）。
  本机离线拿不到 rustls/ring，所以自己实现；**对上的是 RFC 8439 的官方测试向量**
  （§2.3.2 块输出、§2.4.2 加密结果），不是「看起来能跑」。
- 密钥：`SHA256("sheetcore-wire-v1" ‖ salt ‖ 口令)`，再分别展开加密钥与认证钥。
  宿主每次连接生成新 salt，随 `ChallengeSalt` 明文下发。
- **方向位**：两个方向若用同一 nonce，密钥流会重复（等于把两段明文异或在一起）。
  所以 nonce 里带方向字节，收发各一个计数器，重放/乱序直接拒。
- 帧格式：`base64(方向 ‖ 计数器 ‖ 密文 ‖ tag)`。口令为空时保持明文（局域网内网自选）。
- 口令不对时宿主回一句明文「口令不正确」再断开；客户端也接受这一帧明文提示。
- 验证：RFC 向量 2 个；会话往返、篡改一字节必须拒、重放必须拒、错口令必须拒；
  双进程同口令 `ops: 18` 正常同步；裸 socket 实测第一帧是 `ChallengeSalt` 明文、
  随后发明文 Hello 直接被断开；错口令客户端 0 条 ops。

**踩坑**：加密接反过一次——宿主写线程可能在挑战帧之前就收到密钥，
按「有没有会话」判断要不要加密会把挑战帧也加密，握手直接失败。

### v1.13 LET 与嵌套 LAMBDA ✅ 2026-11-06

### v1.4 存储层紧凑化（行内有序向量） ✅ 2026-11-06

**先拆账再动手**：124 字节/格里只有 40 是 `Cell` 本体，约 56 是 hashbrown 槽位开销
（每条目 48 字节 + 控制字节 + 容量余量），剩下才是字符串分配。

所以第一刀砍的是存储结构，不是字符串：

`HashMap<CellRef, Cell>` → `HashMap<u32 行号, Vec<(u32 列号, Cell)>>`（行内按列升序，二分查找）

| 指标 | 之前 | 现在 |
|---|---|---|
| 内存（100 万格混合负载） | 124 字节/格 | **111 字节/格** |
| 152MB 文件全量重算 | 19.1 s | **14.1 s**（−26%） |
| 编辑一格（15k 格连带重算） | 60 ms | 69 ms |
| GUI 工作集 | 182–207 MB | **194 MB** |

重算变快是因为范围扫描变成了连续内存遍历（SUM 一个 1.5 万格区域不再跳哈希表）。

**为什么只降了 13 字节**：每行一个 `Vec` 意味着每行一次分配 + 容量余量（5 个格子通常预留 8 个），
再加上 `HashMap<u32, Vec>` 每行一个条目。实测下来这部分抵消了大半收益。

**结论**：字符串 arena 的收益比我先前估的小（40→32 字节/格 + 省掉 malloc 头，合计约 15–18 字节/格）。
要真正到 60 字节/格，需要**分页列式存储**（所有单元格放在大块 `Vec<Cell>` 里、按列分块），
那是存储层重写，不是加个 arena 能解决的。

## 实测数字（v0.1，2026-11-06）

同一台机器、同一个文件（sample.xlsx，14 个非空格）、启动后静置 7 秒测量。

| 配置 | working set | private | exe |
|---|---:|---:|---:|
| wgpu + 全量中文字体（16 MB） | 308.8 MB | 353.0 MB | 14.07 MB |
| glow(OpenGL) + 全量中文字体 | 105.0 MB | 113.0 MB | 10.12 MB |
| **glow + 内嵌子集字体（2.8 MB）** | **74.0 MB** | **80.9 MB** | **12.76 MB** |

结论：
1. **后端比字体重要得多**。wgpu/DX12 在这台机器上多占 200 MB 以上（显存驻留计入 working set）；换 glow(OpenGL) 直接降到 105 MB。
2. **字体子集再省 31 MB**：用 fontTools 把 `Deng.ttf` 裁成 GB2312 常用字（7,542 字，2.78 MB）并 `include_bytes!` 进二进制，内存 105 → 74 MB，中文渲染无缺字。
3. 最终 v0.1 形态：**74 MB / 12.76 MB exe**，是同场景 wgpu 版的 1/4。

注意：glow 依赖显卡 OpenGL 驱动；在某些远程桌面/无 GPU 环境会白屏（本项目在 RDP 会话里遇到过），需要探测失败时回退 wgpu 或软件渲染。

## 保存链的六个"Excel 判损坏"陷阱（v1.27 排查记录）

真实样本 `real100_extreme.xlsx`（106 MB / 21 表 / 418 万格 / 207 万公式）往返后 Excel 拒收。
用"单特性小样本 + Excel COM 自动打开"做二分，最终定位到六处，全部与**包结构**有关，
不是单元格内容的问题：

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 色阶条件格式判损坏 | `<cfvo>` 与 `<color>` 交错输出 | 先全部 cfvo、再全部 color |
| 2 | 数据验证判损坏 | `formula1/formula2` 写成属性 | 改子元素 |
| 3 | 无 CF 的文件也判损坏 | `dxfs` 为空仍重写 styles.xml | 为空直接返回原样 |
| 4 | 带图片判损坏 | `<a:prstGeom prst="">` 空值 | 统一补 `prst="rect"` |
| 5 | 带表格/批注判损坏 | umya 重写时丢 `<tableParts>`/VML | 未编辑的表整段沿用基准 XML |
| 6 | 大文件判损坏 | 见下 | 见下 |

大文件的六处连锁问题（每修一处都要重新用 Excel 验证）：

1. **工作表被搬家**：umya 一律写到 `xl/worksheets/`，原文件在 `xl/stress/worksheets/`；
   搬家后绘图、图表、打印机设置的相对引用全部失效。→ `rehome_sheets()` 把部件挪回基准路径。
2. **`[Content_Types].xml` 悬空 Override**：搬走后留下 15 条指向不存在部件的声明。
   → `prune_content_types()` + `rebuild_content_types()`（以基准为准重建，只保留实际存在的部件）。
3. **样式 count 对不上**：补 dxf 时 `<dxfs count="50">` 没跟着变 56。→ `normalize_styles_counts()`。
4. **工作表 rels 被抢**：两个目录下的同名表共用一个 rels 路径，后写覆盖前写，
   出现"表里有 `r:id` 但 rels 不存在"。→ `restore_base_sheet_rels()` 统一以基准为准（脏表除外）。
5. **共享字符串没有关系**：骨架沿用基准（内联字符串，无 sharedStrings 关系），
   改写过的表却按 `t="s"` 写 → Excel 解析不出字符串。→ `ensure_shared_strings_rel()` 补关系。
6. **编辑过的表被 umya 整张重写**，丢掉 `<sheetPr>`、绘图引用、扩展区。
   → `merge_sheet_data()`：只把 `<sheetData>` 换进去，其余骨架用基准的。

## B4 外部数据（v1.28）

这一项不是真正的 Power Query —— 没有 M 语言、没有查询折叠、没有多表连接。
做的是实际最常用的两件事，并且**刷新能力随文件走**：

| 能力 | 说明 |
|---|---|
| 导入 CSV/TSV | 自动识别分隔符，数字转数值，`"a,b"` 引号里的分隔符不切 |
| 刷新 | 源文件改了点一下重读；行数列数变化一并更新 |
| 从另一张表取数 | 菜单「数据 → 从另一张表取数…」，填 `销售!A1:C100` |
| 持久化 | 数据源存在工作簿自定义名称 `_sc_src_N` 里（字符串常量），
重开文件后仍可刷新；Excel 打开只多几个名字，不影响计算 |

无界面自检 `SC_B4=1`：

```
[B4] 已导入 3 行 × 3 列（import.csv）
[B4] 第2行 ["张三", "研发", "100"]
[B4] 刷新后 A2=赵六 状态=已刷新 1 个数据源
[B4] 重开后数据源=1 首个=Csv { path: "<workspace>/work/import.csv", delim: ',', header: false }
```

已知边界：
- CSV 路径是绝对路径；换机器/换盘符后刷新会失败（会提示，不会静默清空）。
- 不支持 Excel 的 QueryTable 部件（Excel 里看不到"查询"面板），只保证文件本身合法可开。
- 跨表取数是值复制，不保留公式引用关系。

## 边界收敛（v1.29）

| 边界 | 处理 |
|---|---|
| 另存 143–190 s | **48 s**：补丁攒在暂存里一次落盘，未改动部件 `raw_copy_file` 直搬（不再解压重压缩）。收尾修补 102 s → 7 s |
| CSV 路径绑死绝对路径 | 与工作簿同目录时存相对路径；刷新时先按相对路径解析，绝对路径失效还会在文件同目录找同名文件 |

## B4 升级：真·Excel 查询表（v1.30）

之前只把 CSV 读进单元格，数据源信息存在自定义属性里。现在导入的 CSV 会同时挂成
**Excel 原生 QueryTable**——打开「数据 → 查询和连接」能看到这条查询，右键就能刷新，
刷新走的是 Excel 自己的文本驱动，不经过我们的代码。

实现要点（照着 Excel 2016 实际写出的文件对齐）：

| 部件 | 作用 |
|---|---|
| `xl/connections.xml` | 连接定义：`type="6"`（文本文件）、`textPr@sourceFile`、`codePage="65001"` |
| `xl/queryTables/queryTableN.xml` | 查询表本体，靠 `connectionId` 挂到连接 |
| 工作表 rels | 一条 `queryTable` 关系（工作表 XML 里**没有**对应元素，Excel 只认 rels） |
| `xl/_rels/workbook.xml.rels` | 必须有一条 `connections` 关系，缺了 Excel 直接打不开 |
| workbook.xml | 一条同名定义名称指向目标区域（`localSheetId` 必填） |

踩到的三个坑：

1. **`<textFields>` 不能省**：没有表头时我以为可以省略，结果 Excel 判文件损坏。
   实测 Excel 无论有没有表头都写 `<textFields><textField/></textFields>`。
2. **数据源不能塞进 definedNames**：和查询表自己的同名定义名称冲突，Excel 拒收。
   改存 `docProps/custom.xml`（自定义文档属性，Excel 规范位置）。
3. **`workbook.xml.rels` 缺 connections 关系**：部件齐全但 Excel 打不开。

验证（Excel COM）：

```
Open OK QueryTables=1 A2=赵六
  connection=TEXT;<workspace>\work\import.csv
  Refresh OK A2=赵六     # 改 CSV 后刷新，Excel 自己拉到新值
```
